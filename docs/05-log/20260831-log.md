# Log — 2026-08-31

## เพิ่ม business rule ใหม่ 2 ข้อให้ Call-Saleng — บังคับเหตุผลตอน Admin ยกเลิก และ Admin เปลี่ยนวันที่/เวลานัดรับได้โดยตรง

- User (ผ่าน coordinator) ส่ง requirement ดิบที่ผ่านการคุยกันหลายรอบจนสรุปแล้ว สำหรับ [[../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng: ระบบเรียกรถซาเล้งมารับซื้อขยะ Recycle ที่บ้าน]] ครอบคลุม 2 business rule ใหม่:
  1. **Admin ยกเลิก/ปฏิเสธ (cancel/reject) คำขอ ต้องกรอกเหตุผล (`cancel_reason`) ก่อนจึงจะกดยืนยันได้** ห้ามปล่อยว่าง (อ้างอิงรูปแบบเดียวกับโปรเจกต์ตัวอย่าง LeaveEasy ที่บังคับต้องมี comment ก่อนกด "ไม่อนุมัติ") — field `cancel_reason` มีอยู่แล้วในตาราง `pickup_request` ของ [[../02-design/02-technical/database-schema|database-schema]] แต่ยังไม่ถูกบังคับ required ทั้งใน business rule ของ spec และใน UI จริง (`webapp/admin/dashboard/app.js` ปัจจุบันยังไม่มีช่องกรอกเหตุผลใน modal reject)
  2. **Admin เปลี่ยนวันที่ (`requested_date`) และ/หรือช่วงเวลานัดรับ (`time_slot`) ของคำขอได้โดยตรง มีผลทันทีเมื่อกดยืนยัน** โดยไม่ต้องรอ user reconfirm ก่อน (เลือก flow นี้แทน flow ที่ต้องรอ user ยืนยันเวลาใหม่) และการกระทำนี้**ไม่เปลี่ยนสถานะ (`status`)** ของคำขอ — เป็น action ใหม่ที่ยังไม่เคยมีอยู่ใน spec เดิมเลย (spec เดิมมีแค่ admin accept → open_for_saleng และ admin reject → cancelled เท่านั้น)
- บริบทเพิ่มเติมที่ user ให้มา: กำลังเตรียมส่งอาจารย์แค่ 1 โมดูล คือ "user สร้างคำขอเรียกรถซาเล้ง" + "admin accept/cancel/change-time" เท่านั้น (ไม่รวมฝั่งสาเล้ง/matching ในรอบนี้) ดังนั้น business rule ใหม่ 2 ข้อนี้อยู่ใน scope ที่ต้องพัฒนาจริงตอนนี้ ไม่ใช่ future scope
- **เหตุผลที่แก้ไขเอกสารเดิม (ไม่สร้างไฟล์ spec ใหม่)**: ทั้ง 2 ข้อเป็นการเพิ่ม business rule/ความสามารถของ Admin ให้กับ requirement เดียวกัน (การจัดการคำขอของ Admin) ที่มีอยู่แล้วใน spec นี้ ไม่ใช่ feature/scope ที่แยกจากกันชัดเจน จึงเหมาะกับการต่อยอดเอกสารเดิมมากกว่าแยกไฟล์ใหม่ — requirement ดิบที่ได้รับมาผ่านการยืนยันรายละเอียดกับ user ครบถ้วนแล้ว (ไม่มีจุดที่ต้องถามเพิ่มผ่าน AskUserQuestion ในรอบนี้)
- การแก้ไขที่ทำใน [[../01-requirements/01-spec/20260819-001-saleng-pickup-request|เอกสาร spec เดิม]]:
  - เพิ่มหมายเหตุ "อัปเดต 2026-08-31" ต่อจากสถานะเอกสารที่หัวไฟล์ สรุป business rule ใหม่ 2 ข้อ
  - ปรับ bullet ใน Scope ของ Admin: ระบุว่า cancel/reject ต้องกรอกเหตุผลก่อนยืนยัน และเพิ่ม bullet ใหม่เรื่อง Admin เปลี่ยนวันที่/ช่วงเวลานัดรับได้โดยตรงไม่เปลี่ยนสถานะ
