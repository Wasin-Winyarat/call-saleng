# Log — 2026-08-19

## สร้างเอกสาร requirement แรกของโปรเจกต์: Call-Saleng

- สร้างเอกสาร [[../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng: ระบบเรียกรถซาเล้งมารับซื้อขยะ Recycle ที่บ้าน]] ใน [[../01-requirements/01-spec/index|01-spec]] จาก requirement ดิบที่ user ส่งมา: "ระบบให้ user เรียกรถซาเล้งมาซื้อขยะ recycle ที่บ้าน โดยไม่ต้องขนไปขายที่ร้านรับซื้อของเก่าเอง"
- **เหตุผลที่สร้างใหม่ (ไม่แก้ไขเอกสารเดิม)**: ตรวจสอบ `docs/01-requirements/01-spec/` แล้วพบว่ามีเพียง `index.md` ยังไม่มีเอกสาร spec ใดๆ อยู่ก่อน — นี่คือ requirement แรกของโปรเจกต์ทั้งหมด จึงต้องสร้างไฟล์ใหม่
- **ประเด็นเรื่องการถาม user**: ตาม workflow ของ agent ควรใช้ AskUserQuestion เพื่อถามเรื่อง scope/MVP/บทบาทผู้ใช้ก่อนเขียนเอกสาร แต่ tool ดังกล่าวไม่ได้อยู่ใน tool set ที่ agent มีในรอบนี้ และอยู่ภายใต้ Auto Mode ที่ให้ bias ไปทางทำงานต่อโดยไม่หยุดถ้าไม่ได้ถูก block จริง จึงตัดสินใจ **ตั้งสมมติฐาน MVP ไว้อย่างชัดเจนในเอกสาร** (หัวข้อ "สมมติฐานเบื้องต้น (ต้องยืนยัน)") พร้อมทำ status ของเอกสารเป็น "Draft" และเก็บประเด็นที่ยังไม่ชัดเจนไว้ในหัวข้อ "Open questions" ท้ายเอกสาร แทนการเดาแล้วเขียนเป็นข้อสรุปเด็ดขาด
- สมมติฐานหลักที่ตั้งไว้: (1) มี 2 บทบาท คือ User และ Saleng ยังไม่มี Admin ใน MVP, (2) เป็นระบบ on-demand ไม่ใช่ scheduled pickup, (3) การจับคู่งานให้สาเล้งเลือกรับงานเอง ไม่ auto-assign, (4) ไม่มีระบบตีราคา/ชั่งน้ำหนัก/ชำระเงินในแอป — ตกลงและจ่ายเงินสดหน้างาน, (5) ยังไม่กำหนดขอบเขตพื้นที่ให้บริการ, (6) ไม่มีระบบ rating/loyalty ใน MVP
- Open questions ที่รอ user ยืนยัน: บทบาท Admin, กลไก matching (manual vs auto-assign), ราคากลางอ้างอิงต่อกิโลกรัม, แผนรองรับการชำระเงินออนไลน์ในอนาคต, ขอบเขตพื้นที่ให้บริการเริ่มต้น, ระยะเวลาหมดอายุของคำขอ, ระดับการยืนยันตัวตนสาเล้ง
- สร้างไฟล์ [[../01-requirements/backlog|backlog]] ขึ้นใหม่ (ยังไม่มีมาก่อนในโปรเจกต์) พร้อมเพิ่มแถวอ้างอิงเอกสารข้างต้น สถานะ "Draft (รอยืนยันสมมติฐาน)"

## อัปเดตเอกสาร Call-Saleng ตามคำตอบที่ user ยืนยันสำหรับ Open questions

- User (ผ่าน coordinator) ตอบคำถามที่เปิดอยู่ใน [[../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng: ระบบเรียกรถซาเล้งมารับซื้อขยะ Recycle ที่บ้าน]] แล้ว 4 ข้อ ดังนี้:
  1. **บทบาท Admin**: ต้องมีใน MVP (อนุมัติ/ปฏิเสธสาเล้งที่ลงทะเบียน, ระงับบัญชี user/saleng, assign งานให้สาเล้ง)
  2. **กลไกจับคู่งาน**: ต้องรองรับทั้ง self-pick (สาเล้งกดรับงานเอง) และ admin-assign (Admin มอบหมายงานให้สาเล้งโดยตรง) พร้อมกันใน MVP
  3. **การชำระเงิน**: MVP ยังใช้เงินสดหน้างานเหมือนเดิม แต่ต้องวางแผนรองรับ e-wallet เป็น future phase (ไม่ใช่แค่ไม่ทำเฉยๆ)
  4. **ระยะเวลาหมดอายุคำขอ**: ไม่มี auto-expire — คำขอที่ไม่มีสาเล้งรับงานจะคงสถานะ "รอสาเล้งรับงาน" ต่อไปเรื่อยๆ จนกว่า user จะยกเลิกเอง
- แก้ไขเอกสารเดิม (ไม่สร้างไฟล์ใหม่) เพราะเป็นการยืนยัน/ปรับปรุงเนื้อหาของ requirement เดียวกันที่มีอยู่แล้ว: เพิ่มหัวข้อ "บทบาทผู้ใช้งานในระบบ (ยืนยันแล้ว)" ระบุ 3 roles (User, Saleng, Admin); ย้ายประเด็นที่ยืนยันแล้ว (Admin, matching, payment, expiry) ออกจาก "สมมติฐานเบื้องต้น" และ "Open questions" ไปเป็นข้อสรุปจริงใน Scope (เพิ่ม Admin capabilities, ปรับ Out of scope ให้ e-wallet เป็น future phase), Business rules (matching 2 ช่องทาง, no auto-expire, การอนุมัติสาเล้งโดย Admin) และ User stories (เพิ่ม story ของ Admin 3 เรื่อง); ปรับสถานะเอกสารที่หัวไฟล์เป็น "ยืนยันประเด็นหลักแล้ว เหลือ Open questions อีก 3 ข้อ"
- คงสมมติฐานที่ยังไม่ถูกท้าทาย (on-demand ไม่ใช่ scheduled pickup, ไม่มี rating/loyalty) และ Open questions ที่ยังไม่มีคำตอบ (ราคากลางอ้างอิงต่อกิโลกรัม, ขอบเขตพื้นที่ให้บริการ, ระดับการยืนยันตัวตนสาเล้ง) ไว้ตามเดิม ไม่ได้ตั้งสมมติฐานใหม่ทับ
- อัปเดต [[../01-requirements/backlog|backlog]]: เปลี่ยนสถานะแถวของเอกสารนี้จาก "Draft (รอยืนยันสมมติฐาน)" เป็น "Confirmed บางส่วน (เหลือ Open questions 3 ข้อ: ราคากลาง, พื้นที่ให้บริการ, ระดับยืนยันตัวตนสาเล้ง)"

## ปิด Open questions ทั้งหมดของ Call-Saleng — เอกสารยืนยันครบแล้ว

- User (ผ่าน coordinator) ตอบ Open questions ที่เหลือทั้ง 3 ข้อสุดท้ายใน [[../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng: ระบบเรียกรถซาเล้งมารับซื้อขยะ Recycle ที่บ้าน]] แล้ว:
  1. **ราคากลางอ้างอิงต่อกิโลกรัม**: ต้องการ — เพิ่มเป็น In-scope ของ MVP โดยเป็นราคาอ้างอิงให้ user ประกอบการตัดสินใจเท่านั้น ไม่ผูกกับธุรกรรมจริง Admin เป็นผู้ตั้ง/อัปเดตราคา
  2. **ขอบเขตพื้นที่ให้บริการเริ่มต้น**: เขตอำเภอเมือง จังหวัดเชียงราย ประเทศไทย
  3. **ระดับการยืนยันตัวตนสาเล้ง**: ใช้เบอร์โทร/OTP เท่านั้น ไม่ต้องอัปโหลดเอกสารทะเบียนรถ/บัตรประชาชนใน MVP
- แก้ไขเอกสารเดิม (ไม่สร้างไฟล์ใหม่) เพราะเป็นการปิด Open questions ของ requirement เดียวกัน: ปรับสถานะเอกสารที่หัวไฟล์เป็น "ยืนยันครบทุกประเด็นแล้ว พร้อมแตกไปเป็น 02-plan"; ลบ 3 ข้อออกจาก "สมมติฐานเบื้องต้น" (คงเหลือเฉพาะ on-demand vs scheduled และ ไม่มี rating/loyalty ที่ยังไม่ถูกท้าทาย); เพิ่ม scope ราคากลางอ้างอิง (ทั้งฝั่ง user เห็นราคา และฝั่ง Admin ตั้ง/อัปเดตราคา) พร้อม user story 2 เรื่องใหม่; เพิ่ม business rule เรื่องพื้นที่ให้บริการ (เขตอำเภอเมือง เชียงราย) และปรับ business rule เรื่องยืนยันตัวตนสาเล้งให้ระบุเบอร์โทร/OTP ชัดเจน; ปรับ Out of scope ให้สอดคล้อง (เอาเรื่องราคากลางและยืนยันตัวตนที่เคย "ยังไม่ยืนยัน" ออก เปลี่ยนเป็นข้อสรุปจริง เพิ่มข้อ "การให้บริการนอกเขตอำเภอเมือง เชียงราย" เป็น out of scope ใหม่); เปลี่ยนหัวข้อ "Open questions" ให้ระบุว่าไม่มีประเด็นเหลือแล้ว
- เอกสารนี้ไม่มี Open question ค้างอยู่แล้ว พร้อมนำไปแตกเป็น [[../01-requirements/02-plan/index|02-plan]] และ [[../../02-design/02-technical/index|02-technical]] ในขั้นต่อไป
- อัปเดต [[../01-requirements/backlog|backlog]]: เปลี่ยนสถานะแถวของเอกสารนี้จาก "Confirmed บางส่วน" เป็น "Confirmed (ยืนยันครบทุกประเด็นแล้ว ไม่มี Open question เหลือ พร้อมแตก 02-plan)"

## เพิ่มรายละเอียด function ระดับหน้าจอ/ฟีเจอร์ให้ Call-Saleng (ขยายรายละเอียด ไม่ใช่ requirement ใหม่)

- User (ผ่าน coordinator) ให้รายละเอียด function คร่าวๆ เพิ่มเติมสำหรับ [[../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng: ระบบเรียกรถซาเล้งมารับซื้อขยะ Recycle ที่บ้าน]] ครอบคลุมฝั่ง user (ฟอร์มคำขอละเอียด, โปรไฟล์บันทึกที่อยู่, อัปโหลดรูปสูงสุด 5 ภาพ, เลือกวันที่/ช่วงเวลา 2 ช่วง), ฝั่ง Admin (เห็นรายการคำขอ, แชทกับ user, ปุ่ม confirm/cancel, เลือก assign สาเล้งหรือ approve self-pick, หน้าจัดการรถซาเล้ง, หน้า update ราคากลาง), และฝั่งสาเล้ง (เห็นรายละเอียดงาน, ปุ่มปิดงาน, ปุ่มส่งใบเสร็จเข้าทั้งฝั่ง user และ admin)
- **เหตุผลที่แก้ไขเอกสารเดิม (ไม่สร้างไฟล์ใหม่)**: coordinator ระบุชัดว่าเป็นการขยายรายละเอียดของ requirement เดิมที่ confirm ไปแล้ว ไม่ใช่ scope ใหม่ที่แยกจากกัน — จึงแก้ไข [[../01-requirements/01-spec/20260819-001-saleng-pickup-request|เอกสาร spec เดิม]] โดยตรง
- การแก้ไขที่ทำ: แบ่ง In-scope ของ Scope ออกเป็น 3 กลุ่มย่อยตาม role (User/Admin/Saleng) เพื่อความชัดเจน; เพิ่ม field ของฟอร์มคำขอ (ชื่อ, เบอร์โทร, ที่อยู่+จุดสังเกตที่ผูกกับโปรไฟล์และบันทึกซ้ำได้, รูปถ่ายขยะสูงสุด 5 ภาพ, วันที่ต้องการเข้ารับ, ช่วงเวลา 08:00–13:00 หรือ 13:00–18:00 แทนที่ field ช่วงเวลากว้างๆเดิม); เพิ่มความสามารถของ Admin (เห็นรายการคำขอทั้งหมด, แชทกับ user, confirm/cancel คำขอ, assign สาเล้งหรือเห็น self-pick แล้ว confirm อีกครั้งกับ user ก่อนงานเริ่มจริง, หน้าจัดการรถซาเล้ง, หน้า update ราคากลาง, เห็นใบเสร็จที่สาเล้งส่งมา); เพิ่มความสามารถของสาเล้ง (เห็นรายละเอียด user ในงานที่ต้องเข้ารับ, ปุ่มส่งใบเสร็จที่ต้องปรากฏทั้งฝั่ง user และ admin); เพิ่ม user stories ใหม่ 10 เรื่อง (#12–20); เพิ่ม business rules ใหม่ 3 ข้อ (ต้อง confirm จาก Admin ก่อนงานเริ่มอย่างเป็นทางการไม่ว่าจับคู่ด้วยวิธีใด, จำกัดรูปภาพไม่เกิน 5 ภาพ, ใบเสร็จต้องปรากฏทั้ง 2 ฝั่ง); ปรับ Open questions และสถานะเอกสารที่หัวไฟล์ให้สะท้อนว่าเหลือ Open questions ใหม่ 3 ข้อ (ไม่ใช่ 0 ข้อเหมือนก่อนหน้า)
- **Open questions ใหม่ที่เพิ่มเข้าไป** (เพราะไม่มั่นใจและไม่ต้องการเดาเอง):
  1. รูปแบบและ field ของใบเสร็จที่สาเล้งส่ง (ระบุรายละเอียดน้ำหนัก/ราคาต่อประเภทขยะหรือไม่ หรือเป็นแค่รูปถ่ายใบเสร็จ)
  2. เนื้อหา/ฟีเจอร์ของหน้าจัดการรถซาเล้ง (Saleng management) ของ Admin
  3. ขั้นตอนการ confirm ของ Admin มีกี่ขั้น (confirm ตัวคำขอเบื้องต้น กับ confirm การจับคู่สาเล้ง เป็นขั้นตอนเดียวกันหรือแยกกัน)
- อัปเดต [[../01-requirements/backlog|backlog]]: ปรับสถานะแถวของเอกสารนี้เป็น "Confirmed เชิงนโยบาย/ขอบเขต + เพิ่มรายละเอียด function แล้ว (เหลือ Open questions 3 ข้อระดับรายละเอียด)"

## ปิด Open questions ชุดที่ 3 ของ Call-Saleng (field ใบเสร็จ, หน้าจัดการรถซาเล้ง, ขั้นตอน confirm)

- User (ผ่าน coordinator) ตอบ Open questions ที่เหลือ 3 ข้อใน [[../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng: ระบบเรียกรถซาเล้งมารับซื้อขยะ Recycle ที่บ้าน]] แล้ว:
  1. **field ของใบเสร็จ**: เป็นรายการ (ประเภทขยะ, น้ำหนัก, ราคา) ได้หลายรายการต่อ 1 ใบเสร็จ
  2. **หน้าจัดการรถซาเล้ง**: ครอบคลุมอย่างน้อย 4 ฟีเจอร์ — ดูสถานะสาเล้ง, อนุมัติสมัครสาเล้งใหม่, ระงับสาเล้ง, ดูประวัติงาน
  3. **ขั้นตอน confirm ของ Admin**: มี 2 กรณีตามเส้นทางจับคู่งาน — admin-assign ต้อง confirm สาเล้งก่อนแล้วค่อย confirm กับลูกค้า (2 ขั้น); self-pick ต้อง confirm กับลูกค้าอีกครั้งเพื่อ finalize — ทั้ง 2 กรณีลงท้ายด้วย "admin confirm กับลูกค้า" เสมอ
- แก้ไขเอกสารเดิม (ไม่สร้างไฟล์ใหม่): ปรับ scope หน้าจัดการรถซาเล้งให้ระบุ 4 ฟีเจอร์ชัดเจน, ปรับ business rule เรื่อง confirm ให้อธิบาย 2 กรณีแยกกัน, เพิ่ม business rule/scope เรื่องโครงสร้างใบเสร็จแบบรายการ, ปรับ Open questions ให้ระบุว่าไม่มีประเด็นเหลือแล้ว ณ ขณะนั้น
- อัปเดต [[../01-requirements/backlog|backlog]]: ปรับสถานะเป็น "Confirmed (ยืนยันครบทุกประเด็นแล้ว ไม่มี Open question เหลือ พร้อมแตก 02-design)"

## เพิ่มบริบทปัญหา, แพลตฟอร์ม, และโมเดลธุรกิจ/รายได้ให้ Call-Saleng

- User (ผ่าน coordinator) ให้ข้อมูลสำคัญเพิ่มเติมสำหรับ [[../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng: ระบบเรียกรถซาเล้งมารับซื้อขยะ Recycle ที่บ้าน]] ครอบคลุม 3 เรื่อง: (1) ปัญหาที่มาของระบบ 3 ข้อ (เสียเวลา/ค่าน้ำมัน, ไม่มีที่เก็บขยะโดยเฉพาะทาวน์เฮ้าส์/ร้านอาหารตึกแถว, รถซาเล้งเข้าไม่ถึงพื้นที่ปิดหรือเวลาไม่ตรงกัน), (2) แพลตฟอร์มเป็น Web App แบบ Responsive, (3) โมเดลรายได้ 3 ช่องทาง (ค่าเรียกใช้งาน 20 บาท/ครั้งหักจากค่าขายขยะ, ค่าโฆษณา banner, ค่าสมาชิกรายเดือนสาเล้งแบบมีลำดับความสำคัญ) และโอกาสในอนาคตด้านข้อมูลสิ่งแวดล้อมให้หน่วยงานท้องถิ่น
- **เหตุผลที่แก้ไขเอกสารเดิม (ไม่สร้างไฟล์ใหม่)**: เป็นการขยายรายละเอียด/บริบทของ requirement เดียวกันที่ confirm ไปแล้ว ไม่ใช่ scope ใหม่ที่แยกจากกัน
- การแก้ไขที่ทำ: เพิ่มปัญหา 3 ข้อต่อจากบริบทเดิม; เพิ่มหัวข้อใหม่ "แพลตฟอร์ม (Platform)" ระบุ Web App Responsive; เพิ่มหัวข้อใหม่ "โมเดลธุรกิจ / รายได้ (Business Model)" ครอบคลุม 3 ช่องทางรายได้ พร้อมอธิบายว่าค่าธรรมเนียม 20 บาท/ครั้งต้องอาศัยการบันทึกมูลค่าธุรกรรมจากใบเสร็จมาคำนวณ แม้ MVP จะยังไม่มี payment gateway จริง; เพิ่มหัวข้อใหม่ "โอกาสในอนาคต (Future Opportunities)" เรื่องข้อมูลปริมาณขยะสำหรับหน่วยงานท้องถิ่น; ปรับ business rule เดิมเรื่องราคาซื้อขายขยะให้ระบุชัดว่าระบบต้อง "บันทึก" มูลค่าธุรกรรมเพื่อคำนวณค่าธรรมเนียม แม้จะไม่รับ/จ่ายเงินจริงผ่าน gateway; เพิ่ม business rule ใหม่เรื่องค่าธรรมเนียม 20 บาท/ครั้ง; ปรับสถานะเอกสารที่หัวไฟล์และหัวข้อ Open questions ให้สะท้อนว่าเหลือ Open questions ใหม่ 2 ข้อ
- **Open questions ใหม่ที่เพิ่มเข้าไป** (เพราะเป็นความขัดแย้งเชิง mechanism ระหว่างโมเดลรายได้กับ MVP ที่เป็นเงินสดหน้างานล้วนๆ ไม่ต้องการเดาเอง):
  1. วิธี settle ค่าธรรมเนียมเรียกใช้งาน 20 บาท/ครั้ง เมื่อยังไม่มี e-wallet/payment gateway ใน MVP
  2. ช่องทางชำระค่าสมาชิกรายเดือนของสาเล้ง เมื่อยังไม่มี payment gateway ใน MVP
- อัปเดต [[../01-requirements/backlog|backlog]]: ปรับสถานะเป็น "Confirmed เชิงนโยบาย/ขอบเขต + รายละเอียด function ครบแล้ว (เหลือ Open questions 2 ข้อใหม่: วิธี settle ค่าธรรมเนียม 20 บาท/ครั้ง, ช่องทางชำระค่าสมาชิกรายเดือนสาเล้ง)"

## ปิด Open questions ชุดสุดท้ายของ Call-Saleng — กลไก settle ค่าธรรมเนียมและค่าสมาชิก

- User (ผ่าน coordinator) ตอบ Open questions ที่เหลือ 2 ข้อสุดท้ายใน [[../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng: ระบบเรียกรถซาเล้งมารับซื้อขยะ Recycle ที่บ้าน]] แล้ว:
  1. **วิธี settle ค่าธรรมเนียมเรียกใช้งาน 20 บาท/ครั้ง**: หักออกจากเงินที่ user ได้รับจริง (ไม่ใช่หักเพิ่มจากสาเล้ง) — ตัวอย่าง มูลค่าขยะ 170 บาท → user ได้รับ 150 บาท → platform ได้ค่าธรรมเนียม 20 บาท ส่วนสาเล้ง settle ค่าธรรมเนียมนี้กับ platform ได้ 3 ช่องทาง: (ก) เติมเงินล่วงหน้าเข้า wallet แล้วหักอัตโนมัติทุกครั้งที่ปิดงาน, (ข) โอนเงินชำระเองแบบ manual, (ค) หักเป็นเงินสดหน้าร้านรับซื้อของเก่าที่เป็นเครือข่าย platform เมื่อสาเล้งนำขยะไปขายต่อ
  2. **ช่องทางชำระค่าสมาชิกรายเดือนของสาเล้ง**: เงินสดหรือโอนเงินผ่านธนาคารเอง (manual, นอกระบบ payment gateway ใน MVP)
- แก้ไขเอกสารเดิม (ไม่สร้างไฟล์ใหม่): ปรับหัวข้อ "โมเดลธุรกิจ / รายได้ (Business Model)" ส่วนค่าบริการเรียกใช้งานให้ระบุกลไกการหักเงินและตัวอย่างการคำนวณ พร้อม 3 ช่องทาง settle; เพิ่ม business rule ใหม่ 2 ข้อ (กลไกค่าธรรมเนียม 20 บาท/ครั้งพร้อมตัวอย่างคำนวณและ 3 ช่องทาง settle, ช่องทางชำระค่าสมาชิกรายเดือน); ปรับสถานะเอกสารที่หัวไฟล์และหัวข้อ Open questions เป็น "ยืนยันครบทุกประเด็นแล้ว ไม่มี Open question เหลือ พร้อมแตกไปเป็น 02-plan/02-technical"
- เอกสารนี้ไม่มี Open question ค้างอยู่แล้วทั้งหมด (ปิดครบทุกรอบ) พร้อมนำไปแตกเป็น [[../01-requirements/02-plan/index|02-plan]] และ [[../../02-design/02-technical/index|02-technical]] ในขั้นต่อไป
- อัปเดต [[../01-requirements/backlog|backlog]]: เปลี่ยนสถานะแถวของเอกสารนี้เป็น "Confirmed (ยืนยันครบทุกประเด็นแล้ว ไม่มี Open question เหลือ พร้อมแตก 02-plan/02-technical)"
