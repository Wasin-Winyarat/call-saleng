# Call-Saleng: ระบบเรียกรถซาเล้งมารับซื้อขยะ Recycle ที่บ้าน

> **สถานะเอกสาร:** ยืนยันครบทุกประเด็นแล้ว ไม่มี Open question เหลือ พร้อมแตกไปเป็น [[../02-plan/index|02-plan]] และ [[../../02-design/02-technical/index|02-technical]] — user ยืนยันทั้งประเด็นเชิงนโยบาย/ขอบเขต (บทบาท Admin, กลไกจับคู่งาน self-pick + admin-assign + admin confirm 2 กรณี, นโยบายการชำระเงิน MVP เงินสดหน้างาน + วางแผนรองรับ e-wallet ในอนาคต, ไม่มี auto-expire ของคำขอ, ราคากลางอ้างอิงต่อกิโลกรัมที่ Admin เป็นผู้ตั้ง/อัปเดต, ขอบเขตพื้นที่ให้บริการเขตอำเภอเมือง จังหวัดเชียงราย, ระดับการยืนยันตัวตนสาเล้งด้วยเบอร์โทร/OTP, โครงสร้างใบเสร็จแบบรายการ, ฟีเจอร์หน้าจัดการรถซาเล้ง), บริบทปัญหา, แพลตฟอร์ม (Web App Responsive), และโมเดลธุรกิจ/รายได้ 3 ช่องทาง รวมถึงกลไกการ settle เงินของค่าธรรมเนียมเรียกใช้งานและค่าสมาชิกรายเดือนแล้ว

## บริบท / Background

ปัจจุบันคนที่มีขยะ recycle (เช่น ขวดพลาสติก กระดาษ เศษเหล็ก อลูมิเนียม) ตามบ้านต้องขนขยะไปขายที่ร้านรับซื้อของเก่าด้วยตัวเอง ซึ่งไม่สะดวก (ต้องมีพาหนะ, เสียเวลา, ขยะสะสมจนล้นบ้าน) "call-saleng" คือระบบที่ให้ผู้ใช้ (เจ้าของขยะ) เรียกรถซาเล้ง (คนขับที่รับซื้อของเก่าตามบ้าน) ให้มารับซื้อขยะ recycle ถึงหน้าบ้าน แทนการขนไปขายเอง

โครงการนี้เกิดจากการสังเกตปัญหาจริงของบ้านและร้านค้าเล็กในต่างจังหวัด ซึ่งแยกขยะที่ขายได้ไว้อยู่แล้ว แต่ยังติดปัญหา 3 ข้อหลัก:

1. **เสียเวลาและค่าน้ำมัน** — ต้องขับรถไปขายขยะเองที่ร้านรับซื้อของเก่า
2. **ไม่มีที่เก็บขยะ** — บ้าน ทาวน์เฮ้าส์ หรือร้านอาหารตึกแถว มีพื้นที่จำกัด ทำให้ขวดพลาสติก หลอด หรือเศษเหล็กสะสมจนล้นพื้นที่
3. **รถซาเล้งเข้าไม่ถึงหรือมาคนละเวลา** — โดยเฉพาะในพื้นที่ปิด เช่น หมู่บ้านจัดสรร หรือช่วงที่ร้านค้าปิดไปแล้ว ซึ่งไม่ตรงกับเวลาที่ซาเล้งผ่านมาตามปกติ

## แพลตฟอร์ม (Platform)

ระบบนี้พัฒนาเป็น **Web App แบบ Responsive** — ใช้งานผ่านเว็บเบราว์เซอร์ได้ทั้งบนคอมพิวเตอร์ (desktop) และมือถือ (mobile browser) โดยไม่ใช่ native mobile app (ไม่ต้องติดตั้งผ่าน App Store/Play Store)

## บทบาทผู้ใช้งานในระบบ (ยืนยันแล้ว)

ระบบมี **3 บทบาทหลัก** ใน MVP:

1. **User/เจ้าของขยะ** — คนที่ต้องการขายขยะ recycle และสร้างคำขอเรียกสาเล้ง
2. **Saleng/คนขับ** — ผู้รับซื้อของเก่าที่ขับรถไปรับซื้อตามจุดที่ user เรียก สามารถกดรับงาน (self-pick) ที่เปิดอยู่ได้เอง
3. **Admin/ผู้ดูแลระบบ** — ทำหน้าที่อนุมัติ/ระงับบัญชีสาเล้งและ user, และสามารถ assign คำขอที่เปิดอยู่ให้สาเล้งคนใดคนหนึ่งได้โดยตรง (ดูรายละเอียดใน Scope และ Business rules ด้านล่าง)

## สมมติฐานเบื้องต้น (ต้องยืนยัน)

รายการต่อไปนี้เป็นสมมติฐานที่ยังไม่ได้รับการยืนยัน/ปฏิเสธจาก user (ประเด็นอื่นที่เคยเป็นสมมติฐานหรือ Open question เช่น บทบาท Admin, กลไกจับคู่งาน, นโยบายการชำระเงิน MVP, การหมดอายุคำขอ, ราคากลางอ้างอิง, พื้นที่ให้บริการ, ระดับการยืนยันตัวตนสาเล้ง, โครงสร้างใบเสร็จ, ฟีเจอร์หน้าจัดการรถซาเล้ง, ขั้นตอน confirm ของ Admin, และกลไกการ settle เงินของโมเดลธุรกิจ ได้รับการยืนยันครบแล้วและย้ายไปเป็นข้อสรุปในหัวข้อ Scope/Business rules/User stories/Business Model — เอกสารนี้ไม่มี Open question เหลือแล้ว):

1. **รูปแบบการทำงานเป็น on-demand** (เรียกแล้วรอสาเล้งมาวันนั้น/ช่วงเวลาใกล้ๆ) ไม่ใช่การจองล่วงหน้าเป็นตารางเวลา (scheduled pickup) — ถ้าต้องการ schedule ล่วงหน้าจะเป็น phase ถัดไป
2. **ไม่มีระบบให้คะแนน/รีวิว (rating)** และ **ไม่มีระบบสมาชิก/loyalty point** ใน MVP

## Scope

### สิ่งที่ทำ (In scope — MVP)

#### User — สร้างและจัดการคำขอ

- User สมัครสมาชิก/เข้าสู่ระบบ และมี profile ส่วนตัวที่เก็บข้อมูลไว้ใช้ซ้ำได้ (ชื่อ, เบอร์โทรติดต่อ, ที่อยู่ที่บันทึกไว้)
- User กดปุ่ม "เรียกรถซาเล้ง" เพื่อสร้างคำขอ โดยกรอก/เลือก:
  - ชื่อผู้ติดต่อ และเบอร์โทรติดต่อ (ดึงจาก profile ได้ หรือกรอกใหม่)
  - ที่อยู่ และจุดสังเกต (ดึงจาก "ที่อยู่ที่บันทึกไว้" ใน profile ได้ หรือกรอกที่อยู่ใหม่แล้วเลือกบันทึกเพิ่มในโปรไฟล์) — ที่อยู่ต้องอยู่ใน**พื้นที่ให้บริการของ MVP** (ดู Business rules)
  - รูปถ่ายขยะ อัปโหลดได้สูงสุด **5 ภาพ** ต่อคำขอ
  - วันที่ต้องการให้เข้ารับ
  - ช่วงเวลาที่ต้องการให้เข้ารับ เลือก 1 ใน 2 ช่วง: **08:00–13:00** หรือ **13:00–18:00**
  - ประเภทขยะ recycle โดยประมาณ (เช่น กระดาษ, พลาสติก, เหล็ก, อลูมิเนียม, ขวดแก้ว)
  - ปริมาณโดยประมาณ (เช่น น้อย/กลาง/มาก หรือประมาณกี่กิโลกรัม)
- **ระบบแสดงราคากลางอ้างอิงต่อกิโลกรัมของขยะแต่ละประเภท** (เช่น กระดาษ, พลาสติก, เหล็ก, อลูมิเนียม, ขวดแก้ว) ให้ user เห็นประกอบการตัดสินใจก่อน/ระหว่างสร้างคำขอ — เป็นราคาอ้างอิงเพื่อประเมินมูลค่าเบื้องต้นเท่านั้น **ไม่ผูกกับธุรกรรมจริง** (ราคาซื้อขายจริงยังตกลงหน้างานระหว่าง user และ saleng ตามเดิม)
- User เห็นสถานะคำขอของตัวเอง (รอ Admin ยืนยัน / รอสาเล้งรับงาน / มีสาเล้งรับงานแล้วรอ Admin confirm / ยืนยันแล้วรอเข้ารับ / เสร็จสิ้น / ยกเลิก)
- User สามารถแชทกับ Admin เกี่ยวกับคำขอของตัวเองได้
- User เห็นใบเสร็จที่สาเล้งส่งเข้ามาในระบบของตัวเองหลังงานเสร็จสิ้น
- User หรือ saleng สามารถยกเลิกคำขอได้ก่อนงานเสร็จสิ้น

#### Admin — บริหารจัดการคำขอ, สาเล้ง, และราคากลาง

- Admin เห็นรายการคำขอที่เข้ามาทั้งหมดจาก user พร้อมรายละเอียด (ชื่อ, เบอร์โทร, ที่อยู่, จุดสังเกต, รูปขยะ, วันที่/ช่วงเวลาที่ต้องการ, ประเภท/ปริมาณขยะโดยประมาณ)
- Admin มีช่องแชทกับ user เพื่อสื่อสารเกี่ยวกับคำขอนั้นๆ
- Admin กด **confirm** หรือ **cancel** คำขอของ user แต่ละรายการ
- Admin **เลือก assign สาเล้งที่จะเข้าไปรับงาน** ได้เองโดยตรง หรือปล่อยให้สาเล้งกดรับงานเอง (self-pick) — ไม่ว่าทางใด สุดท้าย Admin ต้อง **confirm กับ user** เป็นขั้นสุดท้ายเสมอก่อนงานจะเริ่มอย่างเป็นทางการ (รายละเอียดขั้นตอนตามกรณี admin-assign และ self-pick ดู Business rules)
- Admin อนุมัติ (approve) หรือปฏิเสธการลงทะเบียนของสาเล้งใหม่ ก่อนให้สิทธิ์เข้าดู/รับงานในระบบ
- Admin มี**หน้าจัดการรถซาเล้ง (saleng management)** ครอบคลุมอย่างน้อย 4 ฟีเจอร์:
  - ดูสถานะสาเล้งแต่ละคน (เช่น ว่าง / กำลังทำงาน / ระงับ)
  - อนุมัติการสมัครของสาเล้งใหม่
  - ระงับ (suspend) บัญชีสาเล้ง
  - ดูประวัติงานของสาเล้งแต่ละคน
- Admin มี**หน้า update ราคากลางขยะต่อกิโลกรัม** ของขยะแต่ละประเภท
- Admin ระงับ (suspend) บัญชี user หรือ saleng ที่ทำผิดกฎหรือมีปัญหาการใช้งาน
- Admin เห็นใบเสร็จที่สาเล้งส่งเข้ามาในระบบงานของ Admin หลังงานเสร็จสิ้น (บันทึกเป็นประวัติธุรกรรม) — ใบเสร็จเป็นรายการ (ประเภทขยะ, น้ำหนัก, ราคา) ได้หลายรายการต่อ 1 ใบเสร็จ (ดู Business rules)

#### Saleng — รับงานและปิดงาน

- Saleng ลงทะเบียน/เข้าสู่ระบบ (ยืนยันตัวตนด้วยเบอร์โทร/OTP) และดูรายการคำขอที่เปิดอยู่ในพื้นที่ที่ตนสนใจ
- Saleng กดรับงาน (self-pick / accept) คำขอที่เปิดอยู่ด้วยตัวเอง (ยังไม่ final จนกว่า Admin confirm)
- Saleng เห็นรายการงานที่ตนต้องเข้าไปรับ พร้อมรายละเอียดของ user (ชื่อ, เบอร์โทร, ที่อยู่, จุดสังเกต, รูปถ่ายขยะ)
- Saleng และ user เห็นข้อมูลติดต่อกันพอสมควร (เช่น เบอร์โทร/ที่อยู่) เพื่อนัดเจอ
- Saleng กดปิดงาน (mark as completed) เมื่อไปรับซื้อขยะเสร็จแล้ว
- Saleng กดปุ่ม**ส่งใบเสร็จ** เข้าระบบ โดยกรอกรายการ (ประเภทขยะ, น้ำหนัก, ราคาต่อประเภทและ/หรือราคารวม) ได้หลายรายการต่อ 1 ใบเสร็จ — ใบเสร็จนี้ต้องปรากฏทั้งฝั่ง user (ในระบบของ user) และฝั่ง Admin (บันทึกเข้าระบบงาน/ประวัติธุรกรรมของ Admin)

### สิ่งที่ไม่ทำ (Out of scope — MVP)

- ระบบชำระเงินออนไลน์ / e-wallet / การตัดเงินผ่านแอป ใน MVP นี้ (ยังใช้เงินสดหน้างานตามที่ user ยืนยัน) — **แต่วางแผนรองรับ e-wallet เป็น future phase** ในเวอร์ชันต่อไป ดังนั้นการออกแบบเชิงเทคนิค (เช่น data model ของคำขอ/ธุรกรรม) ใน [[../../02-design/02-technical/index|02-technical]] ควรเผื่อช่องสำหรับขยายฟีเจอร์นี้ในอนาคต ไม่ใช่ปิดขาดว่าจะไม่ทำเลย
- ระบบตีราคาขยะแบบผูกกับธุรกรรมจริง หรือการยืนยัน/ต่อรองราคาผ่านแอป — MVP มีเพียง**ราคากลางอ้างอิง**เพื่อประกอบการตัดสินใจของ user เท่านั้น (ดู In scope) ราคาซื้อขายจริงยังตกลงหน้างานเอง
- ระบบชั่งน้ำหนักหรือยืนยันปริมาณขยะจริงผ่านแอป
- ระบบให้คะแนน/รีวิวสาเล้งหรือ user
- การจองล่วงหน้าแบบตารางเวลา (recurring/scheduled pickup)
- Admin dashboard เชิงวิเคราะห์/รายงานผล (analytics/reporting) และการตรวจสอบธุรกรรมทางการเงิน — เนื่องจากไม่มีธุรกรรมผ่านระบบใน MVP (ฟังก์ชัน Admin พื้นฐาน เช่น อนุมัติสาเล้ง, ตั้งราคากลาง, และ assign งาน อยู่ใน scope แล้วตามด้านบน)
- ระบบแจ้งเตือน (push notification) แบบ real-time — ใน MVP อาจใช้การ refresh/polling ธรรมดา
- การยืนยันตัวตนสาเล้งแบบเข้มงวด (KYC/เอกสารทะเบียนรถ, บัตรประชาชน) — MVP ยืนยันด้วยเบอร์โทร/OTP เท่านั้น (ดู Business rules)
- การให้บริการนอกเขตอำเภอเมือง จังหวัดเชียงราย — ยังไม่รองรับพื้นที่อื่นใน MVP นี้ (ดู Business rules)

## User stories / Use cases

1. **ในฐานะ user** ที่มีขยะ recycle สะสมอยู่ที่บ้าน ฉันต้องการสร้างคำขอเรียกรถซาเล้งโดยระบุตำแหน่งและประเภทขยะ เพื่อให้มีสาเล้งมารับซื้อโดยไม่ต้องขนไปขายเอง
2. **ในฐานะ user** ฉันต้องการเห็นสถานะคำขอของฉัน (รอรับงาน/มีคนรับแล้ว/เสร็จสิ้น) เพื่อรู้ว่าต้องรอสาเล้งหรือเตรียมขยะไว้ให้พร้อม
3. **ในฐานะ saleng** ฉันต้องการเห็นรายการคำขอที่เปิดอยู่ในพื้นที่ที่ฉันสนใจ พร้อมประเภท/ปริมาณขยะโดยประมาณ เพื่อเลือกงานที่คุ้มค่าคุ้มเวลาก่อนขับรถไปรับ
4. **ในฐานะ saleng** ฉันต้องการกดรับงานคำขอหนึ่งรายการ เพื่อจองสิทธิ์ไปรับซื้อขยะที่บ้านนั้น และป้องกันสาเล้งคนอื่นแย่งงานเดียวกัน
5. **ในฐานะ saleng** ฉันต้องการกดปิดงานเมื่อไปรับซื้อขยะเสร็จแล้ว เพื่อให้สถานะคำขอนั้นอัปเดตเป็น "เสร็จสิ้น"
6. **ในฐานะ user หรือ saleng** ฉันต้องการยกเลิกคำขอ/งานที่รับไว้ได้ ในกรณีที่มีเหตุสุดวิสัย (เช่น สาเล้งไปไม่ถึง, user ไม่อยู่บ้าน)
7. **ในฐานะ Admin** ฉันต้องการอนุมัติหรือปฏิเสธบัญชีสาเล้งที่ลงทะเบียนใหม่ เพื่อควบคุมคุณภาพของผู้ให้บริการในระบบ
8. **ในฐานะ Admin** ฉันต้องการ assign คำขอที่เปิดอยู่ให้สาเล้งคนใดคนหนึ่งได้โดยตรง เพื่อช่วยจัดการงานในกรณีที่ต้องมอบหมายเฉพาะเจาะจง (เช่น คำขอค้างอยู่นานไม่มีใคร self-pick หรือพื้นที่ที่มีสาเล้งน้อย)
9. **ในฐานะ Admin** ฉันต้องการระงับ (suspend) บัญชี user หรือ saleng ที่ทำผิดกฎ เพื่อรักษาความปลอดภัยและคุณภาพของระบบ
10. **ในฐานะ user** ฉันต้องการเห็นราคากลางอ้างอิงต่อกิโลกรัมของขยะแต่ละประเภทตอนสร้างคำขอ เพื่อประเมินมูลค่าขยะของฉันคร่าวๆ ก่อนตัดสินใจเรียกสาเล้ง
11. **ในฐานะ Admin** ฉันต้องการตั้ง/อัปเดตราคากลางอ้างอิงต่อกิโลกรัมของขยะแต่ละประเภท เพื่อให้ user เห็นข้อมูลที่ใกล้เคียงราคาตลาดปัจจุบัน
12. **ในฐานะ user** ฉันต้องการกรอกฟอร์มคำขอแบบละเอียด (ชื่อ, เบอร์โทร, ที่อยู่, จุดสังเกต, รูปถ่ายขยะสูงสุด 5 ภาพ, วันที่และช่วงเวลาที่ต้องการให้เข้ารับ) เพื่อให้ Admin และสาเล้งมีข้อมูลครบก่อนไปรับซื้อขยะจริง
13. **ในฐานะ user** ฉันต้องการเลือกใช้ที่อยู่ที่บันทึกไว้ในโปรไฟล์แทนการกรอกใหม่ทุกครั้ง เพื่อความรวดเร็วในการสร้างคำขอครั้งต่อไป
14. **ในฐานะ user** ฉันต้องการแชทกับ Admin เกี่ยวกับคำขอของฉัน เพื่อสอบถาม/แจ้งรายละเอียดเพิ่มเติมก่อนสาเล้งเข้ามารับ
15. **ในฐานะ Admin** ฉันต้องการเห็นรายการคำขอที่เข้ามาทั้งหมดพร้อมรายละเอียดของ user และรูปถ่ายขยะ เพื่อตรวจสอบความถูกต้องก่อนดำเนินการต่อ
16. **ในฐานะ Admin** ฉันต้องการกด confirm หรือ cancel คำขอของ user แต่ละรายการ เพื่อควบคุมว่าคำขอใดจะเข้าสู่กระบวนการจับคู่สาเล้งจริง
17. **ในฐานะ Admin** ฉันต้องการเห็นเมื่อสาเล้งกดรับงาน (self-pick) แล้ว และ confirm การจับคู่นั้นกับ user อีกครั้งก่อนงานเริ่มจริง เพื่อป้องกันความผิดพลาดในการมอบหมายงาน
18. **ในฐานะ Admin** ฉันต้องการหน้าจัดการรายชื่อรถซาเล้ง เพื่อดูและบริหารบัญชีสาเล้งทั้งหมดในระบบ
19. **ในฐานะ saleng** ฉันต้องการเห็นรายละเอียดของ user (ชื่อ, เบอร์โทร, ที่อยู่, จุดสังเกต, รูปถ่ายขยะ) ในงานที่ฉันต้องเข้าไปรับ เพื่อเตรียมตัวและเดินทางไปถึงได้ถูกต้อง
20. **ในฐานะ saleng** ฉันต้องการกดส่งใบเสร็จเข้าระบบหลังปิดงาน เพื่อให้ user เห็นหลักฐานการซื้อขาย และ Admin มีบันทึกประวัติธุรกรรมของงานนั้น

## Business rules / เงื่อนไข

- **การจับคู่งานมี 2 ช่องทางที่ต้องรองรับร่วมกันใน MVP**: (ก) **Self-pick** — สาเล้งกดรับงานที่เปิดอยู่ด้วยตัวเอง แบบ first-come-first-served และ (ข) **Admin-assign** — Admin เลือก assign คำขอที่เปิดอยู่ให้สาเล้งคนใดคนหนึ่งโดยตรง ไม่ว่าจะรับงานผ่านช่องทางใด คำขอ 1 รายการต้องผูกกับสาเล้งได้เพียง 1 คนเท่านั้น และต้องหายไปจากรายการที่สาเล้งคนอื่นเห็น/กดรับไม่ได้อีกทันทีที่มีคนรับงานแล้ว (ป้องกันการรับงานซ้ำ ไม่ว่าจะ self-pick ชนกับ self-pick หรือชนกับ admin-assign)
- **คำขอต้องผ่านการ confirm จาก Admin กับ user เป็นขั้นสุดท้ายเสมอ ก่อนจึงจะถือว่างานเริ่มอย่างเป็นทางการ** ไม่ว่าจะจับคู่ด้วยวิธีใด โดยมี 2 กรณีตามเส้นทางการจับคู่งาน:
  - **กรณี Admin เลือก assign สาเล้งเอง**: มี 2 ขั้นตอน — (1) Admin confirm การจับคู่กับสาเล้งที่เลือกก่อน แล้ว (2) Admin confirm กับ user อีกครั้งเพื่อ finalize
  - **กรณีสาเล้งกดรับงานเอง (self-pick)**: การกดรับงานของสาเล้งถือเป็นสถานะ "รอ Admin confirm" เท่านั้น ยังไม่ final — Admin ต้องกด confirm กับ user อีกครั้งเพื่อ finalize การจับคู่ที่สาเล้งเลือกเอง
- User ต้องระบุตำแหน่งที่ตั้งที่ชัดเจนพอให้สาเล้งเดินทางไปถึงได้ (ที่อยู่ หรือพิกัด GPS) พร้อมจุดสังเกตเพิ่มเติม
- **จำนวนรูปถ่ายขยะที่อัปโหลดได้ต่อคำขอ จำกัดไม่เกิน 5 ภาพ**
- **โครงสร้างใบเสร็จที่สาเล้งส่งหลังปิดงาน ประกอบด้วยรายการ (ประเภทขยะ, น้ำหนัก, ราคาต่อประเภทและ/หรือราคารวม) โดยมีได้หลายรายการต่อ 1 ใบเสร็จ** และต้องปรากฏทั้งฝั่ง user (ในระบบของ user) และฝั่ง Admin (บันทึกเข้าระบบงาน/ประวัติธุรกรรมของ Admin)
- **คำขอที่ยังไม่มีสาเล้งรับงานจะไม่มีการหมดอายุอัตโนมัติ (no auto-expire)** — คำขอจะคงสถานะ "รอสาเล้งรับงาน" ต่อไปเรื่อยๆ จนกว่า user จะยกเลิกเอง หรือมีสาเล้งกดรับงาน (self-pick) หรือ Admin assign งานให้สาเล้ง
- ราคาซื้อขายขยะเป็นการตกลงกันเองระหว่าง user และ saleng หน้างาน ระบบไม่มีส่วนเกี่ยวข้องกับการกำหนดราคาหรือรับ/จ่ายเงินของธุรกรรมนี้ใน MVP (เป็นเงินสดหน้างาน — ดูแผนรองรับ e-wallet ในอนาคตที่หัวข้อ Out of scope) — แต่ระบบยังต้อง**บันทึก**มูลค่าธุรกรรมนี้ผ่านใบเสร็จเพื่อใช้คำนวณค่าธรรมเนียมเรียกใช้งานของ platform (ดู Business Model)
- **ราคากลางอ้างอิงต่อกิโลกรัมของขยะแต่ละประเภทตั้ง/อัปเดตได้โดย Admin เท่านั้น** และเป็นเพียงข้อมูลอ้างอิงให้ user ประกอบการตัดสินใจ ไม่ใช่ราคาที่ผูกมัดกับธุรกรรมจริง (ราคาซื้อขายจริงยังตกลงหน้างานตามข้อด้านบน)
- **พื้นที่ให้บริการของ MVP จำกัดเฉพาะเขตอำเภอเมือง จังหวัดเชียงราย ประเทศไทย** — คำขอที่มีตำแหน่งอยู่นอกพื้นที่นี้ยังไม่ได้รับการรองรับใน MVP (การขยายพื้นที่ให้บริการเป็นแผนในเวอร์ชันถัดไป)
- สาเล้งต้องลงทะเบียนและ**ได้รับการอนุมัติจาก Admin** ก่อนจึงจะเห็นและรับงานได้ (ป้องกัน anonymous user หรือสาเล้งที่ไม่ผ่านการตรวจสอบเข้ามารับงาน) — **การยืนยันตัวตนสาเล้งใน MVP ใช้เบอร์โทร/OTP เท่านั้น** ไม่ต้องอัปโหลดเอกสารทะเบียนรถหรือบัตรประชาชน
- Admin สามารถระงับ (suspend) บัญชี user หรือ saleng ได้ทุกเมื่อที่พบการทำผิดกฎ โดยบัญชีที่ถูกระงับจะไม่สามารถสร้างคำขอ/รับงานใหม่ได้อีกจนกว่าจะได้รับการปลดระงับ
- **ค่าธรรมเนียมเรียกใช้งาน (platform fee) 20 บาทต่อคำขอที่ขายขยะสำเร็จ หักออกจากเงินที่ user ได้รับจริง (ไม่ใช่หักเพิ่มจากสาเล้ง) และไม่ใช่การหักล่วงหน้า** — ตัวอย่างการคำนวณ: มูลค่าขยะที่ตกลงกัน 170 บาท → user ได้รับ 150 บาท (170 − 20) → platform ได้รับค่าธรรมเนียม 20 บาท ระบบต้องคำนวณค่าธรรมเนียมนี้จากยอดรวมในใบเสร็จที่สาเล้งส่ง (ดูหัวข้อ Business Model ด้านล่าง) สาเล้งต้อง settle ค่าธรรมเนียมนี้กับ platform ผ่าน 1 ใน 3 ช่องทาง: (ก) เติมเงินล่วงหน้าเข้า wallet ในระบบแล้วหักอัตโนมัติทุกครั้งที่ปิดงาน, (ข) โอนเงินชำระเองแบบ manual, หรือ (ค) หักเป็นเงินสดหน้าร้านรับซื้อของเก่าที่เป็นเครือข่าย platform เมื่อสาเล้งนำขยะไปขายต่อ — MVP ยังไม่มี payment gateway ให้ตัดเงินจริงผ่านระบบ (ดู Business Model)
- **ค่าสมาชิกรายเดือนของสาเล้งชำระเป็นเงินสดหรือโอนเงินผ่านธนาคารเอง (manual, นอกระบบ payment gateway ใน MVP)**

## โมเดลธุรกิจ / รายได้ (Business Model)

ระบบมีช่องทางสร้างรายได้ 3 ช่องทาง (ยังไม่ใช่ทั้งหมดที่ต้องพัฒนาใน MVP แต่ระบุไว้เพื่อให้การออกแบบ data model เผื่อรองรับได้):

1. **ค่าบริการเรียกใช้งาน** — เก็บค่าธรรมเนียมรายครั้ง ทุกครั้งที่การขายขยะสำเร็จ เบื้องต้นคิดค่าเรียกครั้งละ **20 บาท** โดย**หักออกจากเงินที่ user (เจ้าของขยะ) ได้รับจริง ไม่ใช่หักเพิ่มจากสาเล้ง** ตัวอย่างเช่น หากมูลค่าขยะที่ตกลงกันคือ 170 บาท สาเล้งจะจ่ายให้ user เพียง **150 บาท** (170 − 20) ส่วน 20 บาทที่เหลือเป็นค่าธรรมเนียมที่สาเล้งต้องส่งต่อ/ชำระให้ platform — เนื่องจากค่าธรรมเนียมนี้คำนวณจากมูลค่าการขายจริง ระบบจึงต้อง "รู้" มูลค่ารวมของการขายในแต่ละงาน โดยอ้างอิงจากใบเสร็จที่สาเล้งส่ง (รายการประเภทขยะ/น้ำหนัก/ราคาที่ตกลงกันแล้ว) เพื่อคำนวณค่าธรรมเนียมที่สาเล้งต้องชำระให้ platform
   - **ช่องทาง settle ค่าธรรมเนียมกับ platform มี 3 ช่องทาง** (MVP ควรรองรับหรืออย่างน้อยระบุไว้เป็นทางเลือก):
     - (ก) **เติมเงินล่วงหน้า (prepaid wallet)** — สาเล้งเติมเงินเข้าบัญชี/wallet ในระบบไว้ก่อน แล้วระบบหักอัตโนมัติทุกครั้งที่ปิดงานสำเร็จ
     - (ข) **โอนเงินชำระเอง (manual)** — สาเล้งโอนเงินชำระค่าธรรมเนียมนอกระบบแล้วแจ้งยืนยันการโอน
     - (ค) **หักเป็นเงินสดหน้าร้าน** — กรณีสาเล้งนำขยะที่รับซื้อมาไปขายต่อที่ร้านรับซื้อของเก่าที่เป็นเครือข่ายของ platform (platform อาจเป็นเจ้าของร้านเอง) ก็ให้หักค่าธรรมเนียมเป็นเงินสดตรงหน้าร้านตอนสาเล้งมาขายขยะต่อ
   - **ระบบยังไม่รับ/จ่ายเงินจริงผ่าน payment gateway ใน MVP** (ราคาซื้อขายขยะยังเป็นเงินสดหน้างานตามเดิม) แต่ต้อง "บันทึก" มูลค่าการขายและคำนวณยอดค่าธรรมเนียมที่สาเล้งค้างชำระ/ชำระแล้วให้ platform ไว้ในระบบ
2. **ค่าโฆษณาในแอป** — มี banner สำหรับลงโฆษณาในพื้นที่ที่กำหนดไว้ในแอป
3. **ค่าสมาชิกรายเดือนสำหรับสาเล้ง/รถในเครือข่าย** — แบบมีระดับ/ลำดับความสำคัญ (เช่น สาเล้งที่เป็นสมาชิกอาจได้เห็นงานก่อนคนอื่น หรือได้สิทธิพิเศษอื่นๆ) — **ชำระเป็นเงินสดหรือโอนเงินผ่านธนาคารเอง (manual, นอกระบบ payment gateway ใน MVP)**

## โอกาสในอนาคต (Future Opportunities)

ข้อมูลปริมาณขยะ recycle ในพื้นที่ที่ระบบเก็บได้จากการทำธุรกรรม (ประเภทขยะ, น้ำหนัก, พื้นที่, ความถี่) อาจเป็นประโยชน์ต่อหน่วยงานท้องถิ่นด้านสิ่งแวดล้อมในอนาคต (เช่น การวางแผนจัดการขยะ, สถิติการรีไซเคิลในพื้นที่) — เรื่องนี้ยังไม่ใช่ scope ของ MVP แต่เป็นทิศทางที่ควรพิจารณาตอนออกแบบ data model ใน [[../../02-design/02-technical/index|02-technical]] ให้เก็บข้อมูลในรูปแบบที่พร้อมนำไปวิเคราะห์/ส่งต่อได้ในอนาคต โดยไม่ต้องสร้างฟีเจอร์รายงาน/analytics จริงใน MVP

ไม่มี Open question ที่ยังรอคำตอบเหลืออยู่ในเอกสารนี้ ณ ตอนนี้ — ประเด็นทั้งหมดที่เคยเปิดไว้ (บทบาท Admin, กลไกจับคู่งาน, นโยบายการชำระเงิน MVP, การหมดอายุคำขอ, ราคากลางอ้างอิง, ขอบเขตพื้นที่ให้บริการ, ระดับการยืนยันตัวตนสาเล้ง, โครงสร้างใบเสร็จ, ฟีเจอร์หน้าจัดการรถซาเล้ง, ขั้นตอน confirm ของ Admin, วิธี settle ค่าธรรมเนียมเรียกใช้งาน 20 บาท/ครั้ง, และช่องทางชำระค่าสมาชิกรายเดือนของสาเล้ง) ได้รับการยืนยันจาก user ครบแล้ว และถูกนำไปสรุปไว้ในหัวข้อ Scope/Business rules/User stories/Business Model ด้านบน เอกสารนี้พร้อมแตกไปเป็น [[../02-plan/index|02-plan]] และ [[../../02-design/02-technical/index|02-technical]] ต่อไป (ประเด็นใหม่ที่อาจพบระหว่างการออกแบบ/วางแผนควรเปิดเป็นคำถามใหม่แยกต่างหาก)
