# User — เลือก/กรอกที่อยู่ + ตรวจสอบพื้นที่บริการ Prototype

## Persona & บริบทการใช้งาน

**User** กดปุ่ม "ขายขยะ" จากหน้าแรกแล้วมาถึงจุดตัดสินใจแรกของการสร้างคำขอ คือเลือกว่าจะใช้ที่อยู่ที่เคยบันทึกไว้หรือกรอกใหม่ ก่อนระบบจะตรวจสอบว่าที่อยู่นั้นอยู่ในพื้นที่ให้บริการหรือไม่ — เป็นขั้นตอน "gate" ที่ user บางส่วนอาจไปต่อไม่ได้ (นอกพื้นที่บริการ)

## อ้างอิงจาก

- Journey: node C "เลือกที่อยู่: ใช้ที่บันทึกไว้ในโปรไฟล์ หรือกรอกใหม่", node E "ตรวจสอบพื้นที่บริการ", node F "แจ้งว่าไม่สามารถสร้างคำขอได้ นอกพื้นที่บริการ" ใน [[../20260820-001-user-pickup-request-journey|User — สร้างและติดตามคำขอเรียกรถซาเล้ง Journey]]
- Feature: [[../../../01-requirements/feature-list#User|เลือกใช้ที่อยู่ที่บันทึกไว้ในโปรไฟล์แทนกรอกใหม่]]
- Business rule: [[../../../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng spec]] — "พื้นที่ให้บริการของ MVP จำกัดเฉพาะเขตอำเภอเมือง จังหวัดเชียงราย ประเทศไทย — คำขอที่มีตำแหน่งอยู่นอกพื้นที่นี้ยังไม่ได้รับการรองรับใน MVP"

## Layout

Header ย้อนกลับ: back chevron + title "เลือกที่อยู่รับซื้อขยะ" (ไม่มี bottom tab bar ตาม navigation pattern ข้อ 5 — เป็น flow ย่อยโฟกัสงานเดียว)

1. **Section "ที่อยู่ที่บันทึกไว้"**: list การ์ดที่อยู่แนวตั้ง (adapt จาก selectable choice card แต่จัดเป็น list เพราะเนื้อหาข้อความยาว) แต่ละใบ: icon หมุดซ้าย + label ที่อยู่ (เช่น "บ้าน", "ร้านค้า") + ที่อยู่แบบย่อ 1–2 บรรทัด + radio indicator ขวา — เมื่อเลือกแล้ว border/พื้นหลัง tint `--color-primary-100`
2. **ปุ่ม "+ กรอกที่อยู่ใหม่"** แบบ border เส้นประ ใต้ list ที่อยู่ที่บันทึกไว้
3. **Inline form กรอกที่อยู่ใหม่** (ขยายแสดงเมื่อเลือกตัวเลือกนี้):
   - Textarea "ที่อยู่เต็ม" (บ้านเลขที่, ถนน, ตำบล, อำเภอ, จังหวัด)
   - Input "จุดสังเกต" (เช่น "ตรงข้ามร้านสะดวกซื้อ")
   - Checkbox "บันทึกที่อยู่นี้ไว้ใช้ครั้งต่อไป" — ติ๊กแล้วแสดง input เพิ่ม "ตั้งชื่อที่อยู่นี้" (เช่น "บ้าน", "ที่ทำงาน")
4. **Sticky footer**: ปุ่ม Primary เต็มความกว้าง "ถัดไป"

## Components & Design Tokens ที่ใช้

- Selectable list card (ปรับจาก selectable choice card pattern ใน DESIGN.md) — border/tint `--color-primary-100` เมื่อเลือก, radius `--radius-md`
- Textarea และ Input — ตาม pattern DESIGN.md, radius `--radius-md`
- ปุ่ม Primary sticky footer — `--color-primary-600`, radius `--radius-lg`, ความสูง ≥44px
- Header ย้อนกลับ ตาม pattern DESIGN.md

## States (Empty / Loading / Error)

- **Empty** — ยังไม่เคยบันทึกที่อยู่ไว้เลย: ซ่อน section "ที่อยู่ที่บันทึกไว้" ทั้งหมด แสดงเฉพาะ inline form กรอกที่อยู่ใหม่แบบเปิดไว้ตั้งแต่แรก (ไม่ต้องกดปุ่มเพิ่มก่อน)
- **Error — นอกพื้นที่บริการ** (สถานะสำคัญของหน้านี้ ตาม journey node F): เมื่อกด "ถัดไป" แล้วระบบตรวจสอบพบว่าที่อยู่ไม่อยู่ในเขตอำเภอเมือง เชียงราย → แสดง full-screen state แทนที่เนื้อหาฟอร์ม:
  - Icon หมุดพร้อมเครื่องหมายตกใจ โทน `--color-danger`
  - ข้อความ H2 "ขออภัย ยังไม่รองรับพื้นที่นี้"
  - ข้อความ Body "ขณะนี้บริการของเราให้บริการเฉพาะเขตอำเภอเมือง จังหวัดเชียงราย เท่านั้น เราจะขยายพื้นที่บริการเพิ่มเติมในอนาคต"
  - ปุ่ม secondary "กลับหน้าแรก" (ไม่มีปุ่ม primary เพิ่ม เพราะ journey นี้จบที่จุดนี้ตาม node F → จบ)
- **Error — กรอกที่อยู่ไม่ครบ**: ปุ่ม "ถัดไป" ถูก disable จนกว่าจะกรอก/เลือกที่อยู่ครบถ้วน พร้อม helper text สีแดงใต้ฟิลด์ที่ขาด
- **Loading**: ปุ่ม "ถัดไป" แสดง spinner ระหว่างระบบตรวจสอบพื้นที่บริการ (เรียก service area check)

## Interaction Notes

- ถ้ามีที่อยู่ default ที่เคยตั้งไว้ในโปรไฟล์ ให้ preselect radio ของที่อยู่นั้นไว้ล่วงหน้า
- การตรวจสอบพื้นที่บริการเกิดขึ้น**หลัง**กด "ถัดไป" เท่านั้น (ไม่ validate แบบ real-time ขณะพิมพ์ เพื่อลด friction ระหว่างกรอก)
- ถ้าผ่านการตรวจสอบพื้นที่บริการ → นำทางไปหน้าฟอร์มสร้างคำขอ พร้อมส่งข้อมูลที่อยู่ที่เลือก/กรอกไว้ติดไปด้วย
- ถ้าเลือก "บันทึกที่อยู่นี้ไว้ใช้ครั้งต่อไป" ที่อยู่จะถูกบันทึกเข้าโปรไฟล์ทันทีที่ผ่านการตรวจสอบพื้นที่บริการสำเร็จ (ไม่บันทึกที่อยู่ที่อยู่นอกพื้นที่บริการ)
