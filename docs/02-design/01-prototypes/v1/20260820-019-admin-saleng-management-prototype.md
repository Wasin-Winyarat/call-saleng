# Admin — จัดการรถซาเล้ง Prototype

## Persona & บริบทการใช้งาน

**Admin** ใช้หน้านี้ควบคุมคุณภาพผู้ให้บริการในระบบ ครอบคลุม 4 ฟีเจอร์ในหน้าเดียวกันตามที่สเปกระบุ ("หน้าจัดการรถซาเล้ง ครอบคลุมอย่างน้อย 4 ฟีเจอร์"): อนุมัติสมัครใหม่, ดูสถานะสาเล้งแต่ละคน, ดูประวัติงาน, และระงับ (suspend) บัญชี

## อ้างอิงจาก

- Journey: node A–K ทั้งหมดใน [[../20260820-004-admin-saleng-management-journey|Admin — จัดการรถซาเล้ง (Saleng Account Management) Journey]]
- Feature: [[../../../01-requirements/feature-list#Admin|ดูสถานะสาเล้งแต่ละคน (หน้าจัดการรถซาเล้ง)]], [[../../../01-requirements/feature-list#Admin|อนุมัติการสมัครของสาเล้งใหม่ (หน้าจัดการรถซาเล้ง)]], [[../../../01-requirements/feature-list#Admin|ระงับ (suspend) บัญชีสาเล้ง (หน้าจัดการรถซาเล้ง)]], [[../../../01-requirements/feature-list#Admin|ดูประวัติงานของสาเล้งแต่ละคน (หน้าจัดการรถซาเล้ง)]]
- Business rule: [[../../../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng spec]] — "การยืนยันตัวตนสาเล้งใน MVP ใช้เบอร์โทร/OTP เท่านั้น ไม่ต้องอัปโหลดเอกสารทะเบียนรถหรือบัตรประชาชน", "สาเล้งต้องลงทะเบียนและได้รับการอนุมัติจาก Admin ก่อนจึงจะเห็นและรับงานได้", "Admin สามารถระงับ (suspend) บัญชี... ได้ทุกเมื่อที่พบการทำผิดกฎ โดยบัญชีที่ถูกระงับจะไม่สามารถ...รับงานใหม่ได้อีกจนกว่าจะได้รับการปลดระงับ"

> **หมายเหตุการออกแบบ (เลือก layout แบบหน้าเดียว master-detail):** สเปกระบุให้ "หน้าจัดการรถซาเล้ง" ครอบคลุมอย่างน้อย 4 ฟีเจอร์ในหน้าเดียวกัน (ไม่ได้แยกเป็นหลายหน้าเมนู) และ orchestrator ระบุให้เลือกได้ทั้งแบบรวมหน้าเดียวหรือ list+detail — เลือกออกแบบเป็น **หน้าเดียวแบบ master-detail** (list ซ้าย + panel รายละเอียดขวา) เพราะบนจอ desktop มีพื้นที่กว้างพอให้ Admin เห็น context ของสาเล้งที่เลือกพร้อมกับ list ทั้งหมดโดยไม่ต้องสลับหน้าไปมา ต่างจาก mobile ที่ต้อง navigate เป็นหน้าแยก

## Layout

Sidebar เดียวกับหน้าอื่นของ Admin (เมนู "รถซาเล้ง" active) เนื้อหาหลัก:

1. **Topbar**: H1 "จัดการรถซาเล้ง" ซ้าย, ช่องค้นหา (ชื่อ/เบอร์โทร) กลาง-ขวา, ไอคอนกระดิ่งแจ้งเตือนสุดขวา
2. **แถบ filter สถานะ** 5 tab พร้อม badge จำนวน: "ทั้งหมด" / "รออนุมัติ" / "ว่าง" / "กำลังทำงาน" / "ระงับ" — tab "รออนุมัติ" เน้น badge สีส้มให้สังเกตง่ายเป็นพิเศษเพราะเป็นงานที่ต้องดำเนินการก่อน
3. **Master-detail สองคอลัมน์**:
   - **คอลัมน์ซ้าย (~35%) — List สาเล้ง**: การ์ดแถวต่อ 1 คน เรียงจาก "รออนุมัติ" ขึ้นก่อนเสมอ (ไม่ว่า filter tab ใด ยกเว้นกำลังกรองเฉพาะ tab อื่น): avatar วงกลม + ชื่อ + เบอร์โทร (บรรทัดรอง) + status pill เล็ก + ไอคอน chevron ขวา แถวที่ถูกเลือกอยู่ พื้นหลัง `--color-primary-100`
   - **คอลัมน์ขวา (~65%) — Detail panel**: รายละเอียดของสาเล้งที่เลือกไว้ (รายละเอียดเนื้อหาดู "Interaction Notes")
4. **Empty selection**: ถ้ายังไม่ได้เลือกใครจาก list (เช่น เพิ่งเข้าหน้าครั้งแรก) detail panel แสดง placeholder ข้อความกลาง panel "เลือกสาเล้งจากรายการด้านซ้ายเพื่อดูรายละเอียด" — ค่าเริ่มต้นระบบเลือกแถวบนสุดของ list ให้อัตโนมัติถ้ามีข้อมูล

**โครงสร้าง Detail panel (เมื่อเลือกสาเล้งแล้ว):**

1. Header panel: ชื่อสาเล้ง + status pill + caption "สมัครเมื่อ {วันที่แบบไทย}"
2. Badge ยืนยันตัวตน: icon เช็คเขียว + ข้อความ "ยืนยันตัวตนด้วยเบอร์โทร/OTP แล้ว" (ไม่มีเอกสารทะเบียนรถ/บัตรประชาชนให้ตรวจสอบเพิ่มตาม business rule)
3. Card ข้อมูลทั่วไป: เบอร์โทร (พร้อมปุ่มโทรวงกลมเล็ก), พื้นที่ที่สนใจ (ตำบล/เขต ที่เลือกไว้ตอนสมัคร)
4. Tab ภายใน panel 2 แท็บ: "ข้อมูลทั่วไป" (active เริ่มต้น) / "ประวัติงาน"
   - **แท็บประวัติงาน**: list การ์ดงานที่เคยเสร็จสิ้น เรียงใหม่สุดก่อน แต่ละแถว: วันที่ปิดงาน, ประเภทขยะ, น้ำหนักรวม, มูลค่ารวม, สถานะ settle ค่าธรรมเนียม platform (pill เล็ก "ชำระแล้ว"/"ค้างชำระ")
5. **Action bar sticky ล่างสุดของ panel** (ปุ่มเปลี่ยนไปตามสถานะปัจจุบันของสาเล้งที่เลือก — ดู Interaction Notes)

## Components & Design Tokens ที่ใช้

- List/job card (ปรับใช้กับรายชื่อสาเล้ง), Contact card, Data table แบบย่อ (ใน "ประวัติงาน"), Confirm dialog, Tab ภายใน panel — ตาม DESIGN.md ตาราง "UI Components & Patterns"
- Status pill 4 สถานะ: "รออนุมัติ" = เทา `--color-neutral-300` + icon นาฬิกา, "ว่าง" = เขียว `--color-success-600` tint + icon เช็ค, "กำลังทำงาน" = ส้ม `--color-accent-amber-500` + icon กำลังเคลื่อนที่, "ระงับ" = terracotta `--color-danger` + icon ห้าม
- ปุ่ม Primary (อนุมัติ) — `--color-primary-600`, ปุ่ม Danger (ปฏิเสธ/ระงับ) — ตัวอักษร/border หรือ fill `--color-danger` แล้วแต่ระดับความรุนแรง
- Radius การ์ด/panel `--radius-md`, พื้นหลังหน้าจอ `--color-neutral-bg`, พื้นหลัง card `--color-neutral-card`

## States (Empty / Loading / Error)

- **Empty — ยังไม่มีสาเล้งสมัครเข้าระบบเลย**: list ซ้ายว่าง + ข้อความ "ยังไม่มีสาเล้งในระบบ"
- **Empty — ไม่พบผลลัพธ์ตามตัวกรอง/คำค้นหา**: ข้อความ "ไม่พบสาเล้งที่ตรงกับเงื่อนไข" พร้อมปุ่ม secondary "ล้างตัวกรอง"
- **Empty — ยังไม่มีประวัติงาน** (ในแท็บประวัติงาน): ข้อความ "สาเล้งคนนี้ยังไม่มีประวัติงานที่เสร็จสิ้น"
- **Loading**: skeleton row ใน list ซ้าย + skeleton content ใน detail panel ระหว่างโหลดข้อมูล
- **Error**: โหลดข้อมูลไม่สำเร็จ → ข้อความ + icon เตือนโทน `--color-danger` พร้อมปุ่ม "ลองใหม่"

## Interaction Notes

Action bar ล่าง detail panel เปลี่ยนตามสถานะของสาเล้งที่กำลังเลือกอยู่:

1. **สถานะ "รออนุมัติ"**: ปุ่ม Primary "อนุมัติ" + ปุ่ม text/danger "ปฏิเสธการสมัคร"
   - กด "อนุมัติ" ไม่ต้องมี confirm dialog เพิ่ม (แก้ไขภายหลังได้ด้วยการ suspend ถ้าพบปัญหา) → สถานะเปลี่ยนเป็น "ว่าง" ทันที สาเล้งได้สิทธิ์เข้าดู/รับงานในระบบ (ดู [[20260820-012-saleng-pending-approval-prototype|Saleng — รอ Admin อนุมัติบัญชี]])
   - กด "ปฏิเสธการสมัคร" → เปิด **Confirm dialog** ("ปฏิเสธการสมัครนี้?" + คำอธิบาย "บัญชีนี้จะไม่ได้รับสิทธิ์เข้าดู/รับงานในระบบ") ตาม UX rule ข้อ 8 เพราะเป็น action ที่กระทบสิทธิ์การใช้งานของผู้สมัคร
2. **สถานะ "ว่าง" หรือ "กำลังทำงาน"**: ปุ่ม Danger เต็มความกว้าง "ระงับบัญชี"
   - กดแล้วเปิด **Confirm dialog** ("ระงับบัญชีสาเล้งนี้?" + คำอธิบาย "สาเล้งจะไม่สามารถรับงานใหม่ได้จนกว่าจะปลดระงับ" + ปุ่ม "ระงับบัญชี" fill `--color-danger` / "ยกเลิก" secondary) ตาม UX rule ข้อ 8
   - ถ้าสถานะปัจจุบันเป็น "กำลังทำงาน" (มีงานค้างอยู่) dialog เพิ่มข้อความเตือน "สาเล้งคนนี้มีงานที่ยังไม่เสร็จสิ้นอยู่ — สเปกยังไม่ได้ระบุว่างานที่ค้างอยู่จะถูกจัดการต่ออย่างไรเมื่อบัญชีถูกระงับ (**รอการออกแบบเพิ่มเติม** ตาม edge case ที่ระบุใน journey doc)"
3. **สถานะ "ระงับ"**: ปุ่ม secondary เต็มความกว้าง "ปลดระงับบัญชี"
   - สเปก/journey doc ไม่ได้ระบุขั้นตอนหรือเงื่อนไขการปลดระงับไว้ชัดเจน (ระบุไว้ว่า "รอการออกแบบเพิ่มเติม") ปุ่มนี้จึงเป็นการออกแบบขั้นต่ำแบบ placeholder เท่านั้น (กดแล้วสถานะกลับเป็น "ว่าง" ทันที ไม่มีขั้นตอนตรวจสอบเพิ่มเติม) — หากต้องมีเงื่อนไข/ขั้นตอนเพิ่มเติมก่อนปลดระงับ (เช่น ระยะเวลาขั้นต่ำ, การอุทธรณ์) ให้แจ้งกลับเพื่อออกแบบเพิ่ม
4. คลิกแถวใน list ซ้าย → เปลี่ยนเนื้อหา detail panel ขวาแบบ in-place ไม่ navigate ออกจากหน้า (SPA-style update)
5. Tab "ข้อมูลทั่วไป"/"ประวัติงาน" ภายใน panel สลับเนื้อหาโดยไม่โหลดหน้าใหม่
