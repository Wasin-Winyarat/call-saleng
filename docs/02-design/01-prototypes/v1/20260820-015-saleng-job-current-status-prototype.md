# Saleng — งานของฉัน (รายละเอียดงานหลัง confirm) Prototype

## Persona & บริบทการใช้งาน

**Saleng** ที่กดรับงานไปแล้ว เข้าหน้านี้เพื่อติดตามว่า Admin confirm การจับคู่หรือยัง ดูข้อมูลติดต่อ user เพื่อนัดเจอ และจัดการงาน (ปิดงาน/ยกเลิก) เป็นหน้าหลักระดับ bottom tab bar เพราะเป็นงานที่สาเล้งต้องเช็คบ่อยที่สุดระหว่างขับรถไปหน้างาน

## อ้างอิงจาก

- Journey: node G "สถานะงาน: รอ Admin confirm ยังไม่ final", node H (จุดตัดสินใจ Admin confirm), node I "งานเป็นของสาเล้งคนนี้อย่างเป็นทางการ", node J "ดูรายละเอียดงาน", node K "เห็นข้อมูลติดต่อของ User", node L (จุดตัดสินใจ "เดินทางไปถึงและซื้อขยะสำเร็จหรือไม่"), node M "สาเล้งกดยกเลิกงานที่รับไว้", node N "ตกลงราคาซื้อขายกับ User หน้างานเป็นเงินสด", node O "กดปิดงาน mark as completed" ใน [[../20260820-002-saleng-job-fulfillment-journey|Saleng — รับงานและปิดงาน (Job Fulfillment) Journey]]
- Feature: [[../../../01-requirements/feature-list#Saleng|ดูรายละเอียดงานที่ต้องเข้าไปรับ]], [[../../../01-requirements/feature-list#Saleng|เห็นข้อมูลติดต่อของ user เพื่อนัดเจอ]], [[../../../01-requirements/feature-list#Saleng|กดปิดงาน (mark as completed)]], [[../../../01-requirements/feature-list#Saleng|ยกเลิกงานที่รับไว้ได้ก่อนงานเสร็จสิ้น]]
- Business rule: [[../../../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng spec]] — "การกดรับงานของสาเล้งถือเป็นสถานะรอ Admin confirm เท่านั้น ยังไม่ final — Admin ต้องกด confirm กับ user อีกครั้งเพื่อ finalize", "User หรือ saleng สามารถยกเลิกคำขอได้ก่อนงานเสร็จสิ้น"

> **หมายเหตุการออกแบบ (inferred):** สอดคล้องกับหมายเหตุในหน้ารายละเอียดงานก่อนกดรับ ระหว่างสถานะ "รอ Admin confirm" prototype นี้ยังไม่เปิดเผยเบอร์โทร/ที่อยู่เต็มของ user (เพราะยังไม่ final อาจถูกยกเลิกหรือปฏิเสธได้) ข้อมูลเต็มจะปรากฏก็ต่อเมื่อสถานะเปลี่ยนเป็น "ยืนยันแล้ว" เท่านั้น หากทีมต้องการเปิดเผยข้อมูลเต็มตั้งแต่ขั้น "รอ Admin confirm" ให้แจ้งกลับเพื่อแก้ไข

## Layout

หน้าหลักระดับ bottom tab bar (ไม่มี back chevron) — ต่างจากหน้าสถานะเทียบเท่าฝั่ง User ที่ใช้ back chevron เพราะฝั่ง User เข้าหน้านี้ผ่านการกด job card เป็นครั้งคราว ส่วนฝั่งสาเล้งงานปัจจุบันเป็นงานหลักที่ต้องเช็คซ้ำบ่อยระหว่างวัน จึงยกระดับเป็นแท็บถาวรแทน

1. **App bar**: H1 "งานของฉัน"
2. **Status hero card** (gradient เขียวเข้ม `--color-primary-700` → `--color-primary-600`, มุมโค้งมาก `--radius-lg`, decorative circle ลายพื้นหลังจางๆ): แสดงสถานะปัจจุบันเป็นตัวใหญ่ (icon + label) — **"รอ Admin confirm"** (โทนกลาง ไม่ใช่สีเตือน) หรือ **"ยืนยันแล้ว"** (โทนเขียวสำเร็จ) พร้อมวันเวลานัดหมายรูปแบบไทย
3. **Card รายละเอียดงาน**:
   - **สถานะ "รอ Admin confirm"**: แสดงเฉพาะ ประเภท/ปริมาณขยะโดยประมาณ, รูปถ่ายขยะ, พื้นที่แบบตำบล/เขต, วันเวลาที่ต้องการให้เข้ารับ — พร้อมข้อความ hint "รายละเอียดที่อยู่และข้อมูลติดต่อเต็มจะแสดงเมื่อ Admin ยืนยันการจับคู่แล้ว"
   - **สถานะ "ยืนยันแล้ว"**: แสดงข้อมูลเต็ม — ที่อยู่แบบเต็ม + จุดสังเกต, ประเภท/ปริมาณขยะโดยประมาณ, รูปถ่ายขยะ, วันเวลาที่ต้องการให้เข้ารับ
4. **Contact card User** (แสดงเฉพาะเมื่อสถานะ = "ยืนยันแล้ว"): avatar วงกลม + ชื่อ user + เบอร์โทร + ที่อยู่แบบย่อ + ปุ่มโทรวงกลมสีเขียวขวาสุด
5. **Caption เตือน**: "ราคาซื้อขายจริงตกลงกันหน้างานเป็นเงินสด ระบบไม่มีส่วนเกี่ยวข้องกับการกำหนดราคานี้"
6. **Sticky footer**:
   - **สถานะ "รอ Admin confirm"**: ปุ่ม outline โทน `--color-danger` เต็มความกว้าง "ยกเลิกงาน" เท่านั้น (ยังกดปิดงานไม่ได้เพราะยังไม่ final)
   - **สถานะ "ยืนยันแล้ว"**: ปุ่ม Primary เต็มความกว้าง "ปิดงาน (ซื้อขายสำเร็จแล้ว)" ด้านบน + ปุ่ม outline โทน `--color-danger` เต็มความกว้าง "ยกเลิกงาน" ด้านล่าง
7. **Bottom tab bar** 3 รายการ: หน้าแรก / งานของฉัน (active, สีเขียว) / โปรไฟล์ (โปรไฟล์ยังไม่ได้ออกแบบหน้าจอในรอบนี้)

## Components & Design Tokens ที่ใช้

- Status hero card, Contact card — ตาม DESIGN.md ตาราง "UI Components & Patterns" ทุกรายละเอียด
- Confirm dialog (modal กลางจอ, radius `--radius-md`) — ใช้ตาม UX rule ข้อ 8 สำหรับทั้งปุ่ม "ปิดงาน" และ "ยกเลิกงาน" (action ที่ย้อนกลับไม่ได้ต้อง confirm ก่อนเสมอ)
- ปุ่มยกเลิก sticky footer — outline `--color-danger`, ไม่ใช่ fill เต็ม เพื่อไม่ให้ดูเป็น primary action ของหน้า (primary action ของหน้านี้คือการติดตามสถานะ/ปิดงาน ไม่ใช่ยกเลิก) ตาม UX rule ข้อ 1
- สถานะทุกจุดมี icon + ข้อความกำกับคู่กับสีเสมอ ตาม UX rule ข้อ 2

## States (Empty / Loading / Error)

- **Empty — ยังไม่มีงานที่กำลังทำอยู่**: แทนที่ status hero card และ card รายละเอียดงานด้วยข้อความ "คุณยังไม่มีงานที่กำลังทำอยู่ตอนนี้" พร้อมปุ่ม Primary "ไปดูรายการคำขอที่เปิดอยู่" → ไปหน้าแรก (job list) ซ่อน sticky footer ปุ่มปิด/ยกเลิกงาน
- **Loading**: skeleton แทนที่ status hero card, card รายละเอียดงาน และ contact card ระหว่างโหลดข้อมูล
- **Error**: โหลดสถานะงานไม่สำเร็จ → แสดง inline error เต็มพื้นที่เนื้อหา พร้อม icon เตือนและปุ่ม "ลองใหม่"

## Interaction Notes

- กดปุ่ม "ยกเลิกงาน" → เปิด **Confirm dialog**: หัวข้อ "ยืนยันยกเลิกงานนี้?" ข้อความอธิบาย "เช่น ไปไม่ถึงหรือ user ไม่อยู่บ้าน — เมื่อยกเลิกแล้วงานนี้จะกลับไปเปิดให้สาเล้งคนอื่นรับต่อได้ทันที" + ปุ่ม 2 ปุ่ม: "ยกเลิกงาน" (fill `--color-danger`, destructive) และ "ไม่ยกเลิก" (secondary/text) — กด "ยกเลิกงาน" แล้วนำทางกลับหน้าแรก (job list) และงานหายจาก "งานของฉัน" ทันที
- กดปุ่ม "ปิดงาน" → เปิด **Confirm dialog**: หัวข้อ "ยืนยันปิดงานนี้?" ข้อความอธิบาย "ยืนยันว่าคุณไปรับซื้อขยะและตกลงราคากับ user เรียบร้อยแล้ว" + ปุ่ม 2 ปุ่ม: "ปิดงาน" (fill `--color-primary-600`) และ "ยกเลิก" (secondary) — กด "ปิดงาน" แล้วนำทางไปหน้าฟอร์มส่งใบเสร็จทันที (บังคับกรอกใบเสร็จก่อนถือว่างานเสร็จสิ้นสมบูรณ์)
- กดปุ่มโทรใน contact card → เปิด native dialer ของอุปกรณ์ (touch target ≥44px ตาม UX rule ข้อ 3)
