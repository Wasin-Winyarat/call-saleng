# Prototype v1 — User, Saleng, Admin

เวอร์ชันแรก (v1) ของ wireframe prototype ครอบคลุมทั้ง 3 persona: **User** (flow เต็มตั้งแต่เข้าสู่ระบบ, สร้างคำขอเรียกรถซาเล้ง, ติดตามสถานะ, จนถึงดูใบเสร็จ), **Saleng** (flow เต็มตั้งแต่เข้าสู่ระบบ, รอ Admin อนุมัติ, ดูรายการงาน, รับงาน, จนถึงปิดงานและส่งใบเสร็จ) และ **Admin** (ดูรายการคำขอทั้งหมด, ตรวจสอบ/confirm/cancel/แชท/จับคู่สาเล้ง, จัดการรถซาเล้ง, จัดการราคากลางขยะ) อ้างอิงจาก [[../DESIGN|DESIGN.md]] ฉบับปัจจุบัน (ยังไม่มีการเปลี่ยนแปลง DESIGN.md ระหว่างทำทั้งสามรอบ), [[../20260820-001-user-pickup-request-journey|User — สร้างและติดตามคำขอเรียกรถซาเล้ง Journey]], [[../20260820-002-saleng-job-fulfillment-journey|Saleng — รับงานและปิดงาน (Job Fulfillment) Journey]], [[../20260820-003-admin-request-matching-journey|Admin — Request Matching Journey]], [[../20260820-004-admin-saleng-management-journey|Admin — Saleng Management Journey]] และ [[../20260820-005-admin-price-management-journey|Admin — Price Management Journey]]

เวอร์ชันนี้เป็น**เวอร์ชันแรก** ยังไม่มีเวอร์ชันก่อนหน้าให้ย้อนดูประวัติการเปลี่ยนแปลง

## หมายเหตุ

- ฟอร์มสร้างคำขอ (หน้าจอ #4) ถูกออกแบบเป็น single-page scrollable form แทน multi-step wizard — เหตุผลและทางเลือกอื่นที่พิจารณาดูได้ในหัวข้อ "อ้างอิงจาก" ของ [[20260820-004-user-request-form-prototype|ไฟล์นั้น]]
- Bottom tab bar ฝั่งสาเล้งใช้ 3 รายการ: หน้าแรก (#13) / งานของฉัน (#15) / โปรไฟล์ (ยังไม่ได้ออกแบบหน้าจอในรอบนี้) — label ปรับให้เหมาะกับบริบทสาเล้งตาม pattern เดียวกับ bottom tab bar ฝั่ง User เนื่องจาก DESIGN.md section 3.4/5 ไม่มีตัวอย่างเฉพาะของ Saleng
- หน้าจอ #14 (รายละเอียดงานก่อนกดรับ) และ #15 (งานของฉัน) จงใจไม่เปิดเผยชื่อ/เบอร์โทร/ที่อยู่เต็มของ user จนกว่า Admin จะ confirm การจับคู่แล้ว เป็นการ inferred design decision จากลำดับ node ใน journey doc — เหตุผลเต็มดูได้ในหัวข้อ "อ้างอิงจาก" ของแต่ละไฟล์นั้น หากทีมต้องการเปิดเผยข้อมูลเต็มตั้งแต่ขั้น self-pick/รอ confirm ให้แจ้งกลับเพื่อแก้ไข
- หน้าจอ #12 (รอ Admin อนุมัติบัญชี) ออกแบบเฉพาะกรณีบัญชีใหม่รอการอนุมัติครั้งแรกเท่านั้น ยังไม่ครอบคลุมกรณีบัญชีถูกระงับ (suspend) ระหว่างมีงานค้างอยู่ ซึ่งเป็น edge case ที่สเปก/journey ระบุว่า "รอการออกแบบเพิ่มเติม" — ยังไม่ได้ออกแบบหน้าจอสำหรับกรณีนี้ในรอบนี้
- **Navigation pattern ของ Admin (#17–#20)**: ใช้ **sidebar navigation แนวตั้งด้านซ้าย** (desktop-first) แทน bottom tab bar เพราะ Admin ใช้งานผ่านคอมพิวเตอร์เป็นหลัก ต่างจาก User/Saleng — adapt token สี/typography/spacing/radius เดิมของ DESIGN.md มาใช้ ไม่มี token ใหม่ เหตุผลเต็มอยู่ในหัวข้อ "อ้างอิงจาก" ของ [[20260820-017-admin-request-list-prototype|หน้ารายการคำขอทั้งหมด]]
- หน้าจอ #19 (จัดการรถซาเล้ง) รวม 4 ฟีเจอร์ตามสเปก (อนุมัติสมัครใหม่, ดูสถานะ, ดูประวัติงาน, suspend) ไว้ใน **ไฟล์เดียวแบบ master-detail** (list ซ้าย + detail panel ขวา) แทนการแยกเป็นหลายหน้า — เหตุผลอยู่ในหัวข้อ "อ้างอิงจาก" ของไฟล์นั้น ปุ่ม "ปลดระงับบัญชี" ในหน้านี้เป็นการออกแบบขั้นต่ำ (placeholder) เพราะสเปก/journey ยังไม่ได้ระบุเงื่อนไข/ขั้นตอนการปลดระงับไว้ชัดเจน
- หน้าจอ #18 (รายละเอียดคำขอ) ยังไม่มีปุ่ม "เปลี่ยนสาเล้งที่ assign ไปแล้ว" ก่อนถึงขั้น confirm กับ user เพราะเป็น edge case ที่ journey doc ระบุว่า "รอการออกแบบเพิ่มเติม" — ถ้าต้องการฟีเจอร์นี้ให้แจ้งกลับ
- หน้าจอ #20 (จัดการราคากลางขยะ) ล็อกตารางไว้ 5 ประเภทขยะคงที่ (กระดาษ/พลาสติก/เหล็ก/อลูมิเนียม/ขวดแก้ว) แก้ไขได้เฉพาะราคา ไม่มีปุ่มเพิ่ม/ลบประเภท เป็นการ inferred design decision เพราะสเปกไม่ได้ระบุให้ Admin เพิ่ม/ลบประเภทขยะได้
