# User — เข้าสู่ระบบ/สมัครสมาชิก Prototype

## Persona & บริบทการใช้งาน

**User** (เจ้าของขยะ recycle ในเขตอำเภอเมือง เชียงราย) เปิดเว็บแอปเป็นครั้งแรก หรือกลับมาใช้งานอีกครั้ง หน้านี้เป็นจุดเริ่มต้นของทุก journey — ต้องผ่านหน้านี้ก่อนจึงจะเข้าถึงฟีเจอร์ใดๆ ของแอปได้ กลุ่มผู้ใช้มีทั้งวัยทำงานและผู้สูงอายุ จึงต้องออกแบบให้ flow สั้น กรอกน้อย ตัวอักษร/ปุ่มใหญ่อ่านง่าย

## อ้างอิงจาก

- Journey: node A "เข้าสู่ระบบ/สมัครสมาชิก" ใน [[../20260820-001-user-pickup-request-journey|User — สร้างและติดตามคำขอเรียกรถซาเล้ง Journey]]
- Feature: [[../../../01-requirements/feature-list#User|สมัครสมาชิก/เข้าสู่ระบบ]] (Must have — inferred)
- Spec: [[../../../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng spec]] — หัวข้อ "Scope > User" ระบุเพียงว่า User สมัครสมาชิก/เข้าสู่ระบบและมี profile ส่วนตัว ไม่ได้ระบุวิธียืนยันตัวตนที่ชัดเจนสำหรับ User (ต่างจาก Saleng ที่สเปกระบุชัดว่าใช้เบอร์โทร/OTP)

> **หมายเหตุการออกแบบ (inferred):** เนื่องจากสเปกไม่ได้ระบุวิธียืนยันตัวตนของ User ไว้ชัดเจน prototype นี้เลือกใช้รูปแบบ **เบอร์โทร + OTP** เพื่อให้สอดคล้องกับแนวทางยืนยันตัวตนของ Saleng ในระบบเดียวกัน และลดความซับซ้อนของการจำรหัสผ่านสำหรับผู้ใช้สูงอายุ — หากทีมต้องการ email/password แทน ให้แจ้งกลับเพื่อแก้ไข

## Layout

หน้าเต็มจอ ไม่มี header ย้อนกลับ และไม่มี bottom tab bar (อยู่นอก main flow ตาม navigation pattern ข้อ 5 ของ DESIGN.md)

1. **โลโก้แบรนด์** กึ่งกลางด้านบน (ตรา mascot สาเล้ง) + tagline เล็กใต้โลโก้ ("บริการเก็บขยะรีไซเคิล — อนุรักษ์สิ่งแวดล้อม ชุมชนสะอาด")
2. **Segmented toggle** 2 ตัวเลือก: "เข้าสู่ระบบ" / "สมัครสมาชิก" (ตัวที่ active = พื้นหลัง `--color-primary-600` ตัวอักษรขาว, inactive = ตัวอักษร `--color-text-secondary`)
3. **ขั้นที่ 1 — กรอกเบอร์โทร**: input เบอร์โทรศัพท์ (label + placeholder "08X-XXX-XXXX") ใต้ input มี helper text "เราจะส่งรหัส OTP ไปยังเบอร์นี้"
4. ปุ่ม Primary เต็มความกว้าง "ขอรหัส OTP"
5. **ขั้นที่ 2 — ยืนยัน OTP** (แสดงแทนที่ขั้นที่ 1 หลังกดขอรหัส): ช่องกรอกเลข OTP 6 หลัก (แยกกล่องทีละหลัก), ข้อความนับถอยหลัง "ขอรหัสใหม่ได้ใน 00:60" → เปลี่ยนเป็นลิงก์ "ส่งรหัสอีกครั้ง" สีเขียวเมื่อครบเวลา
6. ปุ่ม Primary เต็มความกว้าง "ยืนยัน"
7. **เฉพาะกรณีสมัครสมาชิก + OTP ถูกต้อง**: แสดงฟอร์มเพิ่มเติมต่อท้าย — ช่อง "ชื่อ-นามสกุล" (required) เบอร์โทรใช้ค่าที่ยืนยันแล้วไม่ต้องกรอกซ้ำ → ปุ่ม Primary "เริ่มใช้งาน"

## Components & Design Tokens ที่ใช้

- ปุ่ม Primary เต็มความกว้าง — พื้นหลัง `--color-primary-600`, radius `--radius-lg`, ตัวอักษรสีขาว, ความสูง ≥44px ตาม UX rule ข้อ 3
- Segmented toggle — พื้นหลังรวม `--color-neutral-card`, active pill `--color-primary-600`
- Input field — border `--color-neutral-300`, radius `--radius-md`, focus border `--color-primary-600`
- Typography: H1 24px Bold สำหรับหัวข้อ, Body 16px สำหรับ label, Caption 12–13px `--color-text-secondary` สำหรับ helper text/countdown
- Error text ใต้ input ใช้สี `--color-danger` (`#D97757`) พร้อม icon เตือนกำกับเสมอ (ไม่ใช้สีอย่างเดียว ตาม UX rule ข้อ 2)

## States (Empty / Loading / Error)

- **Loading**: ปุ่ม "ขอรหัส OTP" / "ยืนยัน" เปลี่ยนเป็น spinner + disable ปุ่มระหว่างรอ response
- **Error — เบอร์โทรไม่ถูกต้อง**: ข้อความ "กรุณากรอกเบอร์โทรให้ถูกต้อง" สี `--color-danger` ใต้ input พร้อม icon เตือน
- **Error — OTP ผิด/หมดอายุ**: ข้อความ "รหัส OTP ไม่ถูกต้องหรือหมดอายุ กรุณาลองใหม่" ใต้ช่องกรอก OTP, เคลียร์ช่องกรอกอัตโนมัติ
- **Error — เบอร์นี้เคยสมัครแล้ว** (กดสมัครสมาชิกด้วยเบอร์ที่มีบัญชีอยู่แล้ว): แสดง inline message พร้อมลิงก์สลับไปแท็บ "เข้าสู่ระบบ" ให้ทันที
- ไม่มี Empty state สำหรับหน้านี้

## Interaction Notes

- ปุ่ม "ขอรหัส OTP" ถูก disable 60 วินาทีหลังกดเพื่อป้องกันการขอรหัสซ้ำถี่เกินไป
- เมื่อกรอกครบ 6 หลักในช่อง OTP ระบบ auto-submit โดยไม่ต้องกดปุ่ม "ยืนยัน" เพิ่ม (ปุ่มยังคงแสดงไว้เป็นทางเลือกสำรอง)
- สมัครสมาชิกสำเร็จ หรือเข้าสู่ระบบสำเร็จ (เบอร์นี้เคยสมัครแล้ว) → นำทางไปหน้าแรก (Home)
- Toggle ระหว่าง "เข้าสู่ระบบ" กับ "สมัครสมาชิก" จะรีเซ็ตฟอร์มกลับไปขั้นที่ 1 เสมอ
