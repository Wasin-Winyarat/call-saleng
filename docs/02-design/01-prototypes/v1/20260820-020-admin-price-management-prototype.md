# Admin — จัดการราคากลางขยะ Prototype

## Persona & บริบทการใช้งาน

**Admin** เป็นผู้เดียวที่ตั้งและอัปเดตราคากลางอ้างอิงต่อกิโลกรัมของขยะแต่ละประเภท เปิดหน้านี้เมื่อราคาตลาดเปลี่ยนแปลงและต้องการให้ราคาที่ user เห็นตอนสร้างคำขอใกล้เคียงราคาตลาดปัจจุบัน เป็น journey ที่สั้นและไม่มีสาขาซับซ้อน

## อ้างอิงจาก

- Journey: node A–F ทั้งหมดใน [[../20260820-005-admin-price-management-journey|Admin — อัปเดตราคากลางขยะ (Price Management) Journey]]
- Feature: [[../../../01-requirements/feature-list#Admin|อัปเดตราคากลางขยะต่อกิโลกรัมของแต่ละประเภท]]
- Business rule: [[../../../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng spec]] — "ราคากลางอ้างอิงต่อกิโลกรัมของขยะแต่ละประเภทตั้ง/อัปเดตได้โดย Admin เท่านั้น และเป็นเพียงข้อมูลอ้างอิงให้ user ประกอบการตัดสินใจ ไม่ใช่ราคาที่ผูกมัดกับธุรกรรมจริง" — ระบบอัปเดตราคาที่ user เห็นทันทีหลังบันทึก (ดู [[20260820-007-user-price-list-prototype|User — หน้าราคาขยะ]] ฝั่งที่ user เห็นผลลัพธ์)

> **หมายเหตุการออกแบบ (inferred — ล็อกประเภทขยะไว้ 5 ประเภทคงที่):** สเปกระบุตัวอย่างประเภทขยะไว้ 5 ประเภท (กระดาษ, พลาสติก, เหล็ก, อลูมิเนียม, ขวดแก้ว) และไม่มี user story หรือ business rule ใดที่ระบุให้ Admin เพิ่ม/ลบประเภทขยะใหม่ได้ ตารางนี้จึงออกแบบให้มีแค่ 5 แถวคงที่ แก้ไขได้เฉพาะราคา ไม่มีปุ่มเพิ่ม/ลบประเภท หากต้องรองรับประเภทขยะที่เพิ่มได้แบบ dynamic ในอนาคต ให้แจ้งกลับเพื่อออกแบบเพิ่ม

## Layout

Sidebar เดียวกับหน้าอื่นของ Admin (เมนู "ราคากลาง" active) เนื้อหาหลัก:

1. **Topbar**: H1 "จัดการราคากลางขยะ" ซ้าย + caption ใต้หัวข้อ (`--color-text-secondary`) "อัปเดตล่าสุดโดย {ชื่อ Admin} เมื่อ {วันที่แบบไทย}" — ไอคอนกระดิ่งแจ้งเตือนขวาบน
2. **Banner เตือนสั้นๆ**: card เล็กพื้นหลังพาสเทล `--color-accent-peach-100` ข้อความ "ราคานี้เป็นราคาอ้างอิงเท่านั้น ราคาซื้อขายจริงตกลงกันหน้างานระหว่าง user และสาเล้ง ระบบไม่มีส่วนเกี่ยวข้องกับการกำหนดราคานี้"
3. **Data table ราคากลาง** (ตาม DESIGN.md ตาราง "UI Components & Patterns" pattern Data table — header row เข้ม, แถวสลับสีอ่อนบาง): 5 แถวคงที่ ประเภทขยะ: กระดาษ, พลาสติก, เหล็ก, อลูมิเนียม, ขวดแก้ว คอลัมน์:
   - Icon ประเภทขยะ + ชื่อประเภท
   - ราคาปัจจุบัน (ช่วงต่ำสุด–สูงสุด บาท/กก. เช่น "8–12 บาท/กก.")
   - อัปเดตล่าสุด (วันที่แบบไทย เฉพาะแถวนั้น)
   - Action: ปุ่ม icon ดินสอ "แก้ไข"

## Components & Design Tokens ที่ใช้

- Data table (header พื้นหลัง `--color-primary-700` ตัวอักษรขาว, แถว zebra `--color-neutral-card`/`--color-neutral-bg`), Banner เตือน พื้นหลัง `--color-accent-peach-100` radius `--radius-md`
- Typography: ราคาต่อกิโลกรัมใช้ Body 16px ตัวหนา, ชื่อประเภทใช้ Body 16px ปกติ, caption อัปเดตล่าสุดใช้ Caption 12–13px `--color-text-secondary`
- Input แก้ไขราคา (โหมด inline edit): 2 ช่อง number input "ราคาต่ำสุด" / "ราคาสูงสุด" (บาท/กก.) radius `--radius-md` พร้อม helper text ใต้ช่องกรอกตาม UX rule ข้อ 6
- ปุ่ม Primary ขนาดเล็ก "บันทึก" `--color-primary-600`, ปุ่ม text "ยกเลิก" ในแถวที่กำลังแก้ไข

## States (Empty / Loading / Error)

- **Loading**: skeleton row 5 แถวแทนที่ตารางระหว่างโหลดข้อมูลราคา
- **Error**: โหลดราคาไม่สำเร็จ → ข้อความ "โหลดข้อมูลราคาไม่สำเร็จ" พร้อม icon เตือนโทน `--color-danger` และปุ่ม "ลองใหม่"
- ไม่มี Empty state (ตารางมี 5 แถวคงที่เสมอ ไม่มีสถานะไม่มีข้อมูล)

## Interaction Notes

- กดปุ่ม "แก้ไข" ที่แถวใดแถวหนึ่ง → แถวนั้นเปลี่ยนเป็นโหมดแก้ไข inline (คอลัมน์ "ราคาปัจจุบัน" กลายเป็น 2 ช่อง input ราคาต่ำสุด/สูงสุด) พร้อม helper text ใต้ช่อง "ระบุเป็นจำนวนเต็มหรือทศนิยม 1 ตำแหน่ง ราคาสูงสุดต้องมากกว่าหรือเท่ากับราคาต่ำสุด" ตาม UX rule ข้อ 6 — คอลัมน์ action เปลี่ยนเป็นปุ่ม "บันทึก" (primary เล็ก) และ "ยกเลิก" (text)
- แก้ไขได้ทีละ 1 แถวเท่านั้น (กด "แก้ไข" แถวอื่นระหว่างที่มีแถวหนึ่งอยู่ในโหมดแก้ไข จะแจ้งเตือนให้บันทึก/ยกเลิกแถวเดิมก่อน) เพื่อป้องกันความสับสนตาม UX rule ข้อ 1 (1 primary action ต่อครั้ง)
- กด "บันทึก" ไม่ต้องมี Confirm dialog (การแก้ไขราคาไม่ใช่ action ที่ย้อนกลับไม่ได้ตาม UX rule ข้อ 8 — แก้ไขซ้ำได้ทุกเมื่อ) → แสดง toast แจ้งเตือนสั้นๆ พื้นหลังเขียวอ่อน "บันทึกราคา{ชื่อประเภท}สำเร็จ ผู้ใช้จะเห็นราคาใหม่ทันที" พร้อมอัปเดตคอลัมน์ "อัปเดตล่าสุด" ของแถวนั้นเป็นวันที่/เวลาปัจจุบัน ตาม business rule ที่ระบุว่าระบบอัปเดตราคาที่ user เห็นทันที
- กด "ยกเลิก" ระหว่างแก้ไข → แถวกลับเป็นโหมดอ่านอย่างเดียว ไม่มีการเปลี่ยนแปลงค่าที่บันทึกไว้เดิม
- สเปกไม่ได้ระบุเรื่องการเก็บ history ของการเปลี่ยนราคาแต่ละครั้ง (audit trail) — หน้านี้ยังไม่มีปุ่ม/ลิงก์ดูประวัติการเปลี่ยนราคา หากต้องการให้เปิดเป็นคำถามใหม่แยกในขั้นตอนออกแบบเชิงเทคนิคถัดไปตามที่ journey doc ระบุไว้
