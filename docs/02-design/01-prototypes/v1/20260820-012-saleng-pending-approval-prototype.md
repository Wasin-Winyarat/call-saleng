# Saleng — รอ Admin อนุมัติบัญชี Prototype

## Persona & บริบทการใช้งาน

**Saleng** ที่เพิ่งสมัครสมาชิกสำเร็จ (หรือเข้าสู่ระบบซ้ำก่อนได้รับอนุมัติ) แต่บัญชียังไม่ผ่านการตรวจสอบจาก Admin หน้านี้ต้องสื่อสารชัดเจนว่า "ทำไมยังใช้งานไม่ได้" และ "ต้องรออะไร" เพื่อลดความสับสน/กังวลว่าสมัครไม่สำเร็จ

## อ้างอิงจาก

- Journey: node B "บัญชีผ่านการอนุมัติจาก Admin แล้วหรือยัง" (เส้นทาง "ยังไม่อนุมัติ") และ node C "รอ Admin อนุมัติบัญชี ยังเข้าดู/รับงานไม่ได้" ใน [[../20260820-002-saleng-job-fulfillment-journey|Saleng — รับงานและปิดงาน (Job Fulfillment) Journey]]
- Feature: [[../../../01-requirements/feature-list#Saleng|ลงทะเบียน/เข้าสู่ระบบด้วยเบอร์โทร/OTP]]
- Business rule: [[../../../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng spec]] — "สาเล้งต้องลงทะเบียนและได้รับการอนุมัติจาก Admin ก่อนจึงจะเห็นและรับงานได้ (ป้องกัน anonymous user หรือสาเล้งที่ไม่ผ่านการตรวจสอบเข้ามารับงาน)"

## Layout

หน้าเต็มจอ บล็อกการเข้าใช้งานฟีเจอร์หลักทั้งหมด ไม่มี header ย้อนกลับและไม่มี bottom tab bar (ตาม navigation pattern ข้อ 5 — สถานะนี้ยังไม่ใช่ main flow ที่ใช้งานได้จริง)

1. **Status hero card** กึ่งกลางจอ (gradient เขียวเข้ม `--color-primary-700` → `--color-primary-600`, มุมโค้งมาก `--radius-lg`, decorative circle ลายพื้นหลังจางๆ — โทนเดียวกับ status hero card ฝั่ง User): icon นาฬิกา/รอตรวจสอบตรงกลาง + label "รอการตรวจสอบ"
2. **หัวข้อ H2**: "บัญชีของคุณอยู่ระหว่างการตรวจสอบ"
3. **ข้อความอธิบาย** (Body 16px, `--color-text-secondary`): "ทีมงานกำลังตรวจสอบข้อมูลการสมัครของคุณ เมื่ออนุมัติแล้วคุณจะสามารถดูและรับงานได้ทันที กระบวนการนี้อาจใช้เวลาสักครู่"
4. **ปุ่ม secondary** เต็มความกว้าง "ตรวจสอบสถานะอีกครั้ง" (refresh manual — MVP ไม่มี real-time notification ตาม Out of scope ของสเปก)
5. **ปุ่ม text link** สี `--color-danger` ใต้ปุ่ม secondary: "ออกจากระบบ"

## Components & Design Tokens ที่ใช้

- Status hero card — ตาม DESIGN.md ตาราง "UI Components & Patterns" (ใช้โทนเดียวกับสถานะ "รอดำเนินการ" คือ icon+ข้อความสีเทา/เขียวสงบ ไม่ใช้สีที่สื่อว่าเป็น error เพราะการรออนุมัติเป็นขั้นตอนปกติ ไม่ใช่ปัญหา)
- ปุ่ม secondary — border `--color-primary-600`, ตัวอักษรสีเขียว, radius `--radius-lg`, ความสูง ≥44px
- Typography: H2 20px Semibold, Body 16px `--color-text-secondary`

## States (Empty / Loading / Error)

- **Loading**: ปุ่ม "ตรวจสอบสถานะอีกครั้ง" เปลี่ยนเป็น spinner ระหว่างเช็คสถานะกับระบบ
- **Error**: เช็คสถานะไม่สำเร็จ (เช่น network error) → toast สั้น "ตรวจสอบสถานะไม่สำเร็จ ลองใหม่อีกครั้ง" ปุ่มกลับมาเป็นปกติ
- ไม่มี Empty state สำหรับหน้านี้ (หน้านี้ผูกกับบัญชีที่มีอยู่จริงเสมอ)
- **หมายเหตุขอบเขต**: หน้านี้ออกแบบเฉพาะกรณี "บัญชีใหม่รอการอนุมัติครั้งแรก" เท่านั้น ส่วนกรณี "บัญชีถูกระงับ (suspend) ระหว่างมีงานค้างอยู่" เป็นสถานะคนละแบบที่สเปกยังไม่ได้ระบุพฤติกรรมชัดเจน (ดูหัวข้อ "เส้นทางอื่น / Edge case" ใน journey doc) — **ยังไม่ได้ออกแบบหน้าจอสำหรับกรณีระงับบัญชีในรอบนี้ ต้องติดตามต่อ**

## Interaction Notes

- กด "ตรวจสอบสถานะอีกครั้ง" → ระบบเช็คสถานะบัญชีปัจจุบัน ถ้าอนุมัติแล้ว นำทางไปหน้ารายการคำขอที่เปิดอยู่ (หน้าแรกของสาเล้ง) ทันที ถ้ายังไม่อนุมัติ ยังคงอยู่หน้านี้พร้อม toast แจ้ง "ยังอยู่ระหว่างการตรวจสอบ"
- กด "ออกจากระบบ" → เปิด confirm dialog ก่อนออกจากระบบจริงเสมอ ตาม UX rule ข้อ 8 (แม้ไม่ใช่ action ทำลายข้อมูล แต่เพื่อความสม่ำเสมอของ pattern ทั้งระบบ)
- เนื่องจาก MVP ไม่มี push notification (ดู Out of scope ของสเปก) สาเล้งต้องเปิดแอปมาเช็คเองหรือกดปุ่ม refresh — ไม่มีการแจ้งเตือนอัตโนมัติเมื่อ Admin อนุมัติแล้ว
