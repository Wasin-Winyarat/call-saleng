# Saleng — รายละเอียดงานก่อนกดรับ (Self-pick) Prototype

## Persona & บริบทการใช้งาน

**Saleng** กดเข้ามาจาก job card ในรายการคำขอที่เปิดอยู่ เพื่อดูรายละเอียดเพิ่มเติมก่อนตัดสินใจกดรับงาน เป็น flow ย่อยโฟกัสงานเดียว ไม่ใช่หน้าหลัก

## อ้างอิงจาก

- Journey: node E "พบคำขอที่สนใจและยังเปิดอยู่" และ node F "กดรับงาน self-pick คำขอที่เปิดอยู่ แบบ first-come-first-served" ใน [[../20260820-002-saleng-job-fulfillment-journey|Saleng — รับงานและปิดงาน (Job Fulfillment) Journey]]
- Feature: [[../../../01-requirements/feature-list#Saleng|ดูรายการคำขอที่เปิดอยู่ในพื้นที่ที่สนใจ]], [[../../../01-requirements/feature-list#Saleng|กดรับงาน (self-pick) คำขอที่เปิดอยู่]]
- Business rule: [[../../../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng spec]] — "การจับคู่งาน... Self-pick — สาเล้งกดรับงานที่เปิดอยู่ด้วยตัวเอง แบบ first-come-first-served... คำขอ 1 รายการต้องผูกกับสาเล้งได้เพียง 1 คนเท่านั้น", "การกดรับงานของสาเล้งถือเป็นสถานะ รอ Admin confirm เท่านั้น ยังไม่ final"

> **หมายเหตุการออกแบบ (inferred):** สเปกไม่ได้ระบุชัดว่าก่อนกดรับงาน สาเล้งเห็นข้อมูล user (ชื่อ/เบอร์โทร/ที่อยู่เต็ม) มากน้อยแค่ไหน แต่จาก user story และลำดับ node ใน journey ("ดูรายละเอียดงาน" และ "เห็นข้อมูลติดต่อ" ถูกระบุเป็นขั้นตอน**หลัง**ได้รับการ confirm เท่านั้น) prototype นี้จึงออกแบบให้หน้านี้แสดงเฉพาะข้อมูลที่จำเป็นต่อการตัดสินใจรับงาน (ประเภท/ปริมาณขยะ, รูปถ่ายขยะ, ระยะทางโดยประมาณ, ช่วงพื้นที่แบบตำบล/เขต, วันเวลาที่ต้องการ) และ **ยังไม่เปิดเผยชื่อ เบอร์โทร หรือที่อยู่เต็มของ user** จนกว่าจะกดรับและได้รับ Admin confirm แล้ว — เพื่อป้องกันการเปิดเผยข้อมูลส่วนตัวของ user ก่อนมีการจับคู่ที่ final หากทีมต้องการเปิดเผยข้อมูลเต็มตั้งแต่ขั้นนี้ ให้แจ้งกลับเพื่อแก้ไข

## Layout

Header ย้อนกลับ: back chevron + title "รายละเอียดคำขอ" (ไม่มี bottom tab bar)

1. **Photo gallery** รูปถ่ายขยะที่ user แนบมา (แสดงเป็น horizontal scroll thumbnail มุมโค้ง กดเพื่อดูรูปเต็มจอ) — ถ้าไม่มีรูปแนบ แสดง placeholder icon ถังรีไซเคิล
2. **Card สรุปคำขอ**: ประเภทขยะโดยประมาณ (chip หลายอัน เช่น "พลาสติก" "กระดาษ"), ปริมาณโดยประมาณ ("กลาง (5–15 กก.)"), รายละเอียดเพิ่มเติมจาก user (ถ้ามี — ข้อความอิสระ)
3. **Card ตำแหน่งโดยประมาณ**: icon หมุด + ชื่อตำบล/เขต + ระยะทางโดยประมาณจากตำแหน่งปัจจุบันของสาเล้ง (เช่น "≈ 3.2 กม.") — ไม่แสดงที่อยู่เต็ม/จุดสังเกต ตามหมายเหตุการออกแบบด้านบน
4. **Card วันเวลาที่ต้องการให้เข้ารับ**: วันที่แบบไทย + ช่วงเวลา (เช่น "27 ก.ค. 2569 · 08:00–13:00")
5. **Caption เตือน**: "ราคาซื้อขายจริงตกลงกันหน้างานเป็นเงินสด ระบบไม่มีส่วนเกี่ยวข้องกับการกำหนดราคานี้"
6. **Sticky footer**: ปุ่ม Primary เต็มความกว้าง "รับงานนี้"

## Components & Design Tokens ที่ใช้

- Photo upload/gallery pattern (ใช้ thumbnail มุมโค้งแบบเดียวกับ Photo upload grid ใน DESIGN.md แต่เป็น read-only ไม่มีปุ่มลบ/เพิ่ม), Card ทั่วไป radius `--radius-md`
- Choice chip แบบ read-only (แสดงประเภทขยะ) — pill radius `--radius-full`, พื้นหลัง `--color-primary-100`
- ปุ่ม Primary sticky footer — `--color-primary-600`, radius `--radius-lg`, ความสูง ≥44px ตาม UX rule ข้อ 3
- Caption 12–13px `--color-text-secondary` สำหรับข้อความเตือนเรื่องราคา

## States (Empty / Loading / Error)

- **Loading**: skeleton แทนที่ photo gallery และ card สรุปคำขอระหว่างโหลดรายละเอียด
- **Error — โหลดรายละเอียดไม่สำเร็จ**: ข้อความ + icon เตือนโทน `--color-danger` พร้อมปุ่ม "ลองใหม่" เต็มพื้นที่เนื้อหา
- **Error — คำขอนี้ถูกคนอื่นรับไปแล้ว** (race condition ตาม business rule "หายไปจากรายการทันทีที่มีคนรับ"): เมื่อกด "รับงานนี้" แล้วระบบตรวจพบว่ามีสาเล้งคนอื่น self-pick หรือ Admin assign ไปก่อนแล้ว → แสดง modal เต็มจอ "งานนี้มีคนรับไปแล้ว" พร้อมปุ่ม Primary "กลับไปดูรายการงาน" (นำทางกลับหน้ารายการคำขอที่เปิดอยู่)
- ไม่มี Empty state สำหรับหน้านี้ (เข้าถึงได้ต่อเมื่อมี request id จากรายการ)

## Interaction Notes

- กดปุ่ม "รับงานนี้" → เปิด **Confirm dialog**: หัวข้อ "ยืนยันรับงานนี้?" ข้อความอธิบาย "การรับงานนี้จะจองสิทธิ์ของคุณ แต่ต้องรอ Admin ยืนยันอีกครั้งก่อนงานเริ่มอย่างเป็นทางการ" + ปุ่ม 2 ปุ่ม: "รับงานนี้" (fill `--color-primary-600`) และ "ยกเลิก" (secondary/text) — ตาม UX rule ข้อ 8 (แม้ยกเลิกได้ภายหลัง แต่การจองสิทธิ์กระทบสาเล้งคนอื่นทันที จึงควร confirm ก่อน)
- กด "รับงานนี้" สำเร็จ → นำทางไปหน้ารายละเอียดงานหลัง confirm โดยสถานะเริ่มต้นคือ "รอ Admin confirm" ตาม journey node G
- กดรูปถ่ายใน gallery → เปิดดูรูปเต็มจอแบบ lightbox เลื่อนดูรูปถัดไปได้
