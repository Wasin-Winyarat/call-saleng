# Saleng — ฟอร์มส่งใบเสร็จ Prototype

## Persona & บริบทการใช้งาน

**Saleng** กรอกฟอร์มนี้ทันทีหลังกดปิดงาน เพื่อบันทึกรายการขยะที่ซื้อจริง (ประเภท/น้ำหนัก/ราคา) ให้ทั้ง user และ Admin เห็นเป็นหลักฐาน และเพื่อให้ระบบคำนวณค่าธรรมเนียมเรียกใช้งานที่สาเล้งต้อง settle กับ platform

## อ้างอิงจาก

- Journey: node N "ตกลงราคาซื้อขายกับ User หน้างานเป็นเงินสด", node P "กรอกและส่งใบเสร็จเข้าระบบ: ประเภทขยะ น้ำหนัก ราคา หลายรายการได้", node Q "ใบเสร็จปรากฏทั้งฝั่ง User และฝั่ง Admin", node R "ระบบคำนวณค่าธรรมเนียมเรียกใช้งาน 20 บาทจากยอดใบเสร็จ ให้สาเล้ง settle ผ่าน wallet/โอนเอง/หักเงินสดหน้าร้าน" ใน [[../20260820-002-saleng-job-fulfillment-journey|Saleng — รับงานและปิดงาน (Job Fulfillment) Journey]]
- Feature: [[../../../01-requirements/feature-list#Saleng|ส่งใบเสร็จเข้าระบบ]]
- Business rule: [[../../../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng spec]] — "โครงสร้างใบเสร็จที่สาเล้งส่งหลังปิดงาน ประกอบด้วยรายการ (ประเภทขยะ, น้ำหนัก, ราคาต่อประเภทและ/หรือราคารวม) โดยมีได้หลายรายการต่อ 1 ใบเสร็จ", "ค่าธรรมเนียมเรียกใช้งาน (platform fee) 20 บาทต่อคำขอที่ขายขยะสำเร็จ หักออกจากเงินที่ user ได้รับจริง (ไม่ใช่หักเพิ่มจากสาเล้ง)... ตัวอย่าง: มูลค่าขยะ 170 บาท → user ได้รับ 150 บาท → platform ได้รับค่าธรรมเนียม 20 บาท... สาเล้งต้อง settle ผ่าน 1 ใน 3 ช่องทาง: เติมเงินล่วงหน้า wallet / โอนเงินเอง manual / หักเป็นเงินสดหน้าร้านเครือข่าย"

## Layout

Header ย้อนกลับ: back chevron + title "ส่งใบเสร็จ" + subtitle "คำขอ #SL-2607" (ไม่มี bottom tab bar — flow ย่อยโฟกัสงานเดียว)

**1. รายการขยะที่ซื้อ**
- H2 "รายการขยะ" + ลิงก์ "+ เพิ่มรายการ" สีเขียวขวา (Section header + ดูทั้งหมด pattern แต่ใช้เป็นปุ่มเพิ่มแทน)
- **List รายการแบบ editable** (เริ่มต้น 1 แถวว่าง เพิ่มได้ไม่จำกัดตาม business rule "หลายรายการต่อ 1 ใบเสร็จ") แต่ละแถวประกอบด้วย:
  - Dropdown "ประเภทขยะ" (กระดาษ / พลาสติก / เหล็ก / อลูมิเนียม / ขวดแก้ว / อื่นๆ ระบุเอง)
  - Input ตัวเลข "น้ำหนัก (กก.)"
  - Input ตัวเลข "ราคารวมรายการนี้ (บาท)" — helper text เล็กใต้ช่อง "กรอกราคาที่ตกลงกับ user จริง"
  - ปุ่มไอคอนถังขยะ (ลบรายการ) มุมขวาของแถว — ซ่อนถ้าเหลือรายการเดียว (ต้องมีอย่างน้อย 1 รายการเสมอ)
- ปุ่ม text link "+ เพิ่มรายการ" ท้าย list (ปุ่มเดียวกับลิงก์ด้านบน แสดงซ้ำเพื่อความสะดวกเมื่อ list ยาว)

**2. สรุปยอด** (คำนวณอัตโนมัติแบบ real-time จากรายการด้านบน)
- เส้นแบ่งบางๆ `--color-neutral-300` คั่นก่อนส่วนสรุป
- **Subtotal row**: "รวมมูลค่าขยะ" ชิดซ้าย + ยอดรวมชิดขวา
- **Fee row**: "ค่าธรรมเนียมบริการ (20 บาท/คำขอ)" ชิดซ้าย + "-20 บาท" ชิดขวา (มีเครื่องหมาย "-" กำกับชัดเจน ตาม UX rule ข้อ 2)
- **Total row** (ตัวหนา ขนาดใหญ่กว่าแถวอื่น, H3 18px Semibold): "ยอดที่ user จะได้รับ" ชิดซ้าย + ยอดสุทธิชิดขวา สีเขียว `--color-success-600`
- Caption ใต้สรุปยอด: "ค่าธรรมเนียม 20 บาทนี้หักจากยอดที่ user ได้รับ ไม่ใช่หักเพิ่มจากคุณ — คุณต้อง settle ค่าธรรมเนียมนี้กับ platform ตามช่องทางที่เลือกด้านล่าง"

**3. ช่องทาง settle ค่าธรรมเนียม**
- H2 "ช่องทางชำระค่าธรรมเนียม"
- Selectable choice card แนวตั้ง 3 ตัวเลือก (เลือกได้ 1):
  1. "หักจาก Wallet" — meta text "ยอดคงเหลือ: {X} บาท" (ถ้ายอดไม่พอ แสดง warning inline ใต้ตัวเลือกนี้)
  2. "โอนเงินเอง" — เมื่อเลือก แสดง sub-section แนบสลิปโอนเงิน (photo upload 1 รูป) + input "เลขอ้างอิงการโอน" (ไม่บังคับ)
  3. "หักเงินสดหน้าร้านเครือข่าย" — meta text "ชำระตอนนำขยะไปขายต่อที่ร้านในเครือข่าย platform"

**4. Sticky footer**
- ปุ่ม Primary เต็มความกว้าง "ส่งใบเสร็จ" — disable จนกว่าจะมีอย่างน้อย 1 รายการที่กรอกครบ (ประเภท+น้ำหนัก+ราคา) และเลือกช่องทาง settle แล้ว (ถ้าเลือก "โอนเงินเอง" ต้องแนบสลิปก่อนจึงกดส่งได้)

## Components & Design Tokens ที่ใช้

- Editable list row, Dropdown, Input ตัวเลข — ตาม pattern Input ของ DESIGN.md, radius `--radius-md`, border `--color-neutral-300`
- Selectable choice card (ช่องทาง settle) — border/tint `--color-primary-100` เมื่อเลือก ตาม DESIGN.md
- Photo upload (สลิปโอนเงิน) — ใช้ pattern เดียวกับ Photo upload grid ของ DESIGN.md แต่จำกัด 1 รูป
- Summary rows/Total row — ตาม pattern เดียวกับหน้าใบเสร็จฝั่ง User (Body 16px รายการทั่วไป, H3 18px Semibold สำหรับ total)
- ปุ่ม Primary sticky footer — `--color-primary-600`, radius `--radius-lg`, ความสูง ≥44px

## States (Empty / Loading / Error)

- **Error — กรอกรายการไม่ครบ**: highlight border สีแดงที่ field ที่ขาด + helper text อธิบายใต้ field เมื่อพยายามกด "ส่งใบเสร็จ" ทั้งที่ปุ่ม disable
- **Error — Wallet ยอดไม่พอ** (เลือกช่องทาง "หักจาก Wallet" แต่ยอดคงเหลือน้อยกว่าค่าธรรมเนียม): inline warning สี `--color-danger` ใต้ตัวเลือกนั้น "ยอดคงเหลือไม่พอ กรุณาเลือกช่องทางอื่นหรือเติมเงินก่อน" พร้อม disable ปุ่ม "ส่งใบเสร็จ" ถ้ายังเลือกช่องทางนี้ค้างไว้
- **Error — ส่งใบเสร็จไม่สำเร็จ** (เช่น network error): inline banner ด้านบนสุดของฟอร์ม "ส่งใบเสร็จไม่สำเร็จ กรุณาลองใหม่อีกครั้ง" พร้อมปุ่ม "ลองใหม่" — ข้อมูลที่กรอกไว้ไม่หายเพื่อไม่ให้ต้องกรอกซ้ำ
- **Loading**: ปุ่ม "ส่งใบเสร็จ" เปลี่ยนเป็น spinner + disable ระหว่างส่งข้อมูล
- ไม่มี Empty state สำหรับหน้านี้ (เป็นฟอร์มกรอกใหม่เสมอ เริ่มต้นด้วย 1 แถวว่าง)

## Interaction Notes

- ยอด subtotal/fee/total คำนวณ real-time ทันทีที่แก้ไขราคารายการใดๆ ไม่ต้องกดปุ่มคำนวณแยก
- กด "ส่งใบเสร็จ" สำเร็จ → แสดงหน้า/modal สรุป "ปิดงานสำเร็จ" พร้อมยอดสุทธิ แล้วนำทางกลับหน้าแรก (job list) — งานนี้หายจาก "งานของฉัน" เพราะสถานะเปลี่ยนเป็น "เสร็จสิ้น" แล้ว
- ใบเสร็จที่ส่งแล้วแก้ไขไม่ได้ผ่านหน้านี้อีก (ถือเป็นบันทึกประวัติธุรกรรม) — ถ้ากรอกผิดต้องติดต่อ Admin ผ่านช่องทางแชท (นอก scope ของหน้านี้)
- การเลือกช่องทาง settle เป็นการเลือกวิธี "จะชำระอย่างไร" บันทึกไว้ในระบบ ไม่ใช่การตัดเงินจริงทันทีผ่าน payment gateway (MVP ยังไม่มี payment gateway ตาม Out of scope ของสเปก) ยกเว้นกรณี "หักจาก Wallet" ที่หักยอดคงเหลือในระบบทันที
