# Saleng — รายการคำขอที่เปิดอยู่ (หน้าแรก) Prototype

## Persona & บริบทการใช้งาน

**Saleng** ที่ผ่านการอนุมัติจาก Admin แล้ว เปิดหน้านี้เป็นประจำระหว่างวันเพื่อหางานที่คุ้มค่าคุ้มเวลาในพื้นที่ที่สนใจ ก่อนตัดสินใจกดรับ เป็นหน้าหลักระดับ bottom tab bar ที่สาเล้งใช้บ่อยที่สุด

## อ้างอิงจาก

- Journey: node D "ดูรายการคำขอที่เปิดอยู่ในพื้นที่ที่สนใจ พร้อมประเภท/ปริมาณขยะโดยประมาณ" และ node E (จุดตัดสินใจ "พบคำขอที่สนใจและยังเปิดอยู่หรือไม่") ใน [[../20260820-002-saleng-job-fulfillment-journey|Saleng — รับงานและปิดงาน (Job Fulfillment) Journey]]
- Feature: [[../../../01-requirements/feature-list#Saleng|ดูรายการคำขอที่เปิดอยู่ในพื้นที่ที่สนใจ]]
- Business rule: [[../../../01-requirements/01-spec/20260819-001-saleng-pickup-request|Call-Saleng spec]] — "คำขอ 1 รายการผูกกับสาเล้งได้เพียง 1 คนเท่านั้น และต้องหายไปจากรายการที่สาเล้งคนอื่นเห็น/กดรับไม่ได้อีกทันทีที่มีคนรับงานแล้ว", "คำขอที่ยังไม่มีสาเล้งรับงานจะไม่มีการหมดอายุอัตโนมัติ (no auto-expire)", "พื้นที่ให้บริการของ MVP จำกัดเฉพาะเขตอำเภอเมือง จังหวัดเชียงราย"

## Layout

หน้าหลักระดับ bottom tab bar (ไม่มี back chevron) ตาม navigation pattern ข้อ 5 ของ DESIGN.md

1. **App bar ทักทาย**: avatar วงกลมซ้าย + ข้อความ "สวัสดี คุณ{ชื่อสาเล้ง}" + ไอคอนกระดิ่งแจ้งเตือนขวาบน (มี badge ตัวเลขถ้ามีแจ้งเตือนใหม่)
2. **Filter chip แถวเดียว เลื่อนแนวนอนได้**: chip แรก "พื้นที่: {เขต/ตำบลที่สนใจ} ▾" (กดเปิด dropdown/modal เลือกพื้นที่ได้หลายรายการ ค่าเริ่มต้นดึงจากพื้นที่ที่ตั้งไว้ตอนสมัคร) ตามด้วย chip ประเภทขยะ (กระดาษ/พลาสติก/เหล็ก/อลูมิเนียม/ขวดแก้ว) ให้กรองรายการเฉพาะประเภทที่สนใจ — chip ที่เลือกอยู่ fill `--color-primary-600`
3. **Section header + จำนวนคำขอ**: H2 "คำขอที่เปิดอยู่" ซ้าย, badge ตัวเลขจำนวนคำขอที่ตรงตัวกรองขวา
4. **List / job card** ต่อ 1 คำขอ เรียงจากใหม่สุดก่อน: icon กล่องซ้าย (แทนประเภทขยะหลัก), บรรทัดแรก "ประเภทขยะโดยประมาณ" (เช่น "พลาสติก, กระดาษ") + meta text บรรทัดสอง "ปริมาณ: กลาง (5–15 กก.) · ระยะทาง ≈ 3.2 กม." + บรรทัดสาม "พื้นที่: {ตำบล/เขต} · วันที่นัด {วันที่ไทย} {ช่วงเวลา}" ไม่แสดงที่อยู่เต็ม/เบอร์โทร/ชื่อ user ในขั้นนี้ (สงวนไว้จนกว่าจะกดรับและได้รับ confirm ตาม business rule ความเป็นส่วนตัว) + chevron ขวา → กดไปหน้ารายละเอียดงานก่อนกดรับ
5. **Bottom tab bar** 3 รายการ: หน้าแรก (active, สีเขียว) / งานของฉัน / โปรไฟล์ (โปรไฟล์ยังไม่ได้ออกแบบหน้าจอในรอบนี้)

## Components & Design Tokens ที่ใช้

- App bar ทักทาย, Section header, List/job card, Bottom tab bar — ตาม DESIGN.md ตาราง "UI Components & Patterns"
- Filter chip — pill radius `--radius-full`, active fill `--color-primary-600` ตัวอักษรขาว, inactive border `--color-neutral-300` ตัวอักษร `--color-text-primary`
- Radius การ์ดทั่วไป `--radius-md`, พื้นหลังหน้าจอ `--color-neutral-bg`, พื้นหลัง card `--color-neutral-card`
- Icon ทุกจุดมี label กำกับเสมอ ตาม UX rule ข้อ 4

## States (Empty / Loading / Error)

- **Empty — ไม่มีคำขอเปิดอยู่ตรงตัวกรอง**: แสดงภาพประกอบเรียบง่าย + ข้อความ "ยังไม่มีคำขอเปิดอยู่ในพื้นที่ที่คุณสนใจตอนนี้ ลองขยายพื้นที่หรือกลับมาเช็คใหม่ภายหลัง" พร้อมปุ่ม secondary "ปรับพื้นที่ที่สนใจ" (เปิด filter พื้นที่)
- **Loading**: skeleton card (พื้นหลังเทาอ่อน shimmer) แทนที่ list ระหว่างโหลดข้อมูล
- **Error**: โหลดรายการไม่สำเร็จ → ข้อความ "โหลดข้อมูลไม่สำเร็จ" พร้อม icon เตือนโทน `--color-danger` และปุ่ม secondary "ลองใหม่"

## Interaction Notes

- MVP ไม่มี real-time push (ดู Out of scope ของสเปก) รายการนี้ควร refresh อัตโนมัติเป็นระยะ (polling) หรือมีปุ่ม pull-to-refresh เพื่อให้เห็นคำขอใหม่/คำขอที่ถูกคนอื่นรับไปแล้วหายจากลิสต์ตาม business rule
- กดไอคอนกระดิ่ง → ไปหน้าแจ้งเตือน (นอก scope ชุดนี้ อาจเป็น placeholder ว่าง)
- กด job card → ไปหน้ารายละเอียดงานก่อนกดรับ หากคำขอนั้นถูกคนอื่นรับไปแล้วก่อนกดเข้าไปถึง (race condition) ระบบจะแจ้ง error ที่หน้าถัดไปแทนที่จะบล็อกตั้งแต่หน้านี้
- แท็บ "งานของฉัน" นำทางไปหน้าสถานะงานปัจจุบัน — ถ้าสาเล้งยังไม่มีงานที่รับอยู่เลย จะเห็น empty state ของหน้านั้นแทน (ดู [[20260820-015-saleng-job-current-status-prototype|หน้างานของฉัน]])
